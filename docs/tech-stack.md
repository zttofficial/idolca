# 技術選型

## 產品定位

K-pop 小卡的鏈上倉儲交易平台：實物入庫鑑定，每張卡在 Solana 上對應一個 NFT；成交時卡留在倉庫，NFT 在鏈上轉移；持有人隨時可以銷毀 NFT，換取實物寄出。價格標 USD，用 Solana 上的 USDT 或 Arc 上的 USDC 結算（Arc 見 [arc.md](arc.md)）。

用戶有兩種登入方式，登入框裡並列，互不衝突：
- **加密用戶**：用 MetaMask、Phantom、Solflare、Backpack 等支援 Solana 的瀏覽器錢包簽名登入，上鏈的卡直接進自己的錢包。
- **粉絲**：用郵箱和密碼註冊，不需要錢包；上鏈的卡由平台錢包代管，不用懂助記詞和 Gas。

這樣首頁和產品都是 Web3 的，但不把不懂加密的粉絲擋在門外。

## Web3

| 層 | 選擇 | 理由 |
|---|---|---|
| 鏈 | **Solana** | 卡牌 RWA 的主戰場（約 63% 的代幣化卡牌交易在 Solana）；Magic Eden、Tensor、Jupiter 都能直接交易；手續費不到 1 美分 |
| 網路切換 | `NEXT_PUBLIC_SOLANA_CLUSTER`（`devnet` / `mainnet-beta`） | 每個網路的公開地址（平台錢包、兩個集合、託管程序、結算代幣）各存一份 `src/lib/chain/<cluster>.json`，換網路只改這個變數，不改代碼。水龍頭、測試幣標籤只在 devnet 出現 |
| 帳號 | 自建：郵箱 + 密碼，或錢包簽名 | 帳號存在自己的資料庫，不依賴第三方登入服務。密碼用 Node 內建 scrypt 加鹽雜湊；錢包登入是 Sign In With Solana 的簡化版：伺服器發一段帶一次性隨機數的訊息（5 分鐘有效、用過即作廢），錢包簽名後伺服器用 ed25519 驗簽，地址第一次出現就建帳號。兩種方式都換成同一種會話：令牌放 httpOnly cookie，資料庫只存它的 SHA-256。Google、Apple 登入和郵箱驗證暫不做 |
| 錢包 | Wallet Standard（`@wallet-standard/app`） | 直接偵測瀏覽器裡的 MetaMask、Phantom、Solflare、Backpack 等 Solana 錢包，不經過第三方連接服務；一個都沒有時連到 Solana 官方的錢包列表。郵箱帳號的卡由平台錢包代管 |
| 卡片 NFT | **Metaplex Core**，金庫卡和自由上鏈的收藏卡各一個集合，都帶平台可改的 `verification` 鑑定狀態 | 一張卡一個帳戶，鑄造成本約 0.003 SOL；Attributes 插件存屬性（編號、團體、成員、專輯、版本、類型、評級機構、分數、鑑定編號、庫位、入庫日期），FreezeDelegate、BurnDelegate 插件管提貨，集合上的 Royalties 插件收二級市場版稅 |
| 計價與結算 | 標 **USD**；Solana 上用 **USDT（SPL）** 結算，Arc 上用 USDC | 前台只標 USD、不換算當地貨幣，付款時才寫明扣哪種幣（見「首頁」）；託管程序同時接受 USDT 和 USDC；主網用 Tether 的官方 USDT，devnet 沒有官方 USDT，用平台自鑄的測試幣 |
| 鏈上程序 | Anchor 1.x（Rust） | 自寫一個最小的掛單託管程序：賣家掛單時 NFT 轉進以資產地址為種子的 PDA，買家付款後原子交換，平台抽成在同一筆交易內扣除；只接受平台集合的資產和 USDT、USDC，抽成上限 10% |
| 鏈上數據讀取 | Solana RPC（`SOLANA_RPC_URL`） | 金庫卡清單在資料庫，持有人、掛單、凍結狀態按清單批量讀鏈（`getMultipleAccounts`）；主網換付費 RPC，避免公共節點限流 |
| 抽卡隨機數 | 承諾—揭示（HMAC-SHA256） | 不依賴第三方 VRF：開賣前公開種子的雜湊，每抽的隨機數由種子和買家錢包產生的付款簽名決定，結束後公開種子，任何人都能重算（見「盲盒卡包」） |

### 鏈上流程

| 動作 | 鏈上發生什麼 |
|---|---|
| 入庫 | 實物鑑定通過後，後台建立金庫卡並鑄造 Core NFT 給寄存人的錢包；平台自有庫存（卡包卡池）鑄給平台錢包 |
| 掛單、成交 | NFT 進託管程序；買家付 USDT，NFT 和款項在同一筆交易裡交換；取消掛單時 NFT 退回賣家 |
| 外部交易 | Core NFT 可以在 Magic Eden、Tensor 直接買賣，不經過平台 |
| 提貨 | 持有人在一筆交易裡：把銷毀權委託給平台、以平台為凍結代理立即凍結、付運費（備註寫卡片 id）。寄出時平台在同一筆交易裡解凍並銷毀。取消時平台解凍、交還兩個委託並退運費 |
| 開盲盒 | 買家付 USDT 進平台錢包；平台對帳後按承諾的種子從卡池抽卡，把抽到的那張金庫卡 NFT 從平台錢包轉給買家 |
| 即時回購 | 平台按卡在卡包裡的價值的 70% 付 USDT：持有人把 NFT 轉給平台、平台付款，兩步在同一筆交易裡（平台先簽付款，持有人簽轉移）；卡回到卡池 |

### 存貨證明

- 公開的金庫頁（`/vault`）：列出每個編號對應的 NFT 地址、持有人、狀態（在庫、掛單中、提貨中）和入庫日期，持有人和狀態直接讀鏈；點編號進卡片頁看正反面照片。
- 未銷毀的 NFT 總數必須等於倉庫實物數量：提貨中的卡還在倉庫裡，NFT 凍結但未銷毀；寄出時才銷毀。正式營運後定期公布盤點結果。
- 平台不持有永久凍結權或永久銷毀權，只有持有人主動申請提貨時才臨時委託給平台。

### 不做

- **不發平台代幣。** 代幣會讓產品被看成炒幣，加重粉絲反感和監管風險；先證明交易本身成立。

## 後端與基礎設施

| 層 | 選擇 | 理由 |
|---|---|---|
| 資料庫 | PostgreSQL + Drizzle ORM | 線上用 Neon（在 Vercel Marketplace 一鍵接入，連線字串自動填入 `DATABASE_URL`；接入時設了變數前綴也認得，會找以 `_DATABASE_URL` 結尾的變數）；本機開發沒有 `DATABASE_URL` 時用 PGlite（嵌入式 Postgres，資料在 `.data/`）。表結構由 `BOOTSTRAP_SQL` 在第一次連線時建立和補欄位，全部可重複執行。必須一起生效的多條寫入走 `atomic()`（`src/lib/server/db.ts`）：Neon 的 HTTP 驅動不支援互動式交易，用 batch（整批在同一個交易裡），PGlite 用一般交易。每個網路用自己的資料庫：devnet 的帳號、卡片和訂單不帶到主網 |
| 圖片存儲 | PostgreSQL `media` 表 | 卡片正反面照片和資料一起存進資料庫，不另接存儲服務，也不放進代碼倉庫。經 `/api/media/{id}` 提供並長期快取，Vercel 的 CDN 擋掉重複請求。照片量大到撐不住資料庫容量時，只換 `src/lib/server/media.ts` 的實現，遷到 Cloudflare R2 這類對象存儲，網址格式不變 |
| 排程 | Vercel Cron 每天呼叫 `/api/cron/daily`（`CRON_SECRET` 保護） | 處理逾時的擔保訂單、清除過期的收件地址、刪掉過期的會話和登入挑戰碼 |
| 頻率限制 | 資料庫計數（`rate_limits` 表） | 不另接服務，多個伺服器實例共用：登入每個 IP 15 分鐘 20 次，註冊每小時 10 個，錢包挑戰碼 10 分鐘 60 次，自由上鏈每個帳號每小時 30 張 |
| 法幣入金（第二階段） | MoonPay 等入金服務 | 用信用卡買 USDT |
| 部署 | Vercel（前端）、Anchor 程序部署到 Solana | — |
| 包管理 | npm | 本機已有，不另裝 |

## 後台與權限

- 後台（`/admin`）只給管理員帳號：資料庫裡 `role` 是 `admin` 的帳號（`npm run admin:grant -- <郵箱或錢包>` 授予），或錢包地址在 `ADMIN_WALLETS` 裡的帳號。環境變數只認錢包，因為錢包登入有簽名證明；郵箱沒有驗證，不能靠郵箱授權。管理員在帳號選單裡看得到後台入口，所有後台接口在伺服器端按會話檢查。
- 後台處理：入庫（拍正反面、填卡片資料和倉位，鑄造金庫 NFT；或把寄進金庫的收藏卡轉成金庫卡）、盲盒卡包（建卡包、把平台自有卡放進卡池並設等級和價值）、擔保交易（退款或放款，申訴中的排最前面）、提貨（看收件地址和運費是否到帳、出貨銷毀、取消並退運費）、標記假卡。

## 市場瀏覽

- 參考兩個競品：KOCA 主打「切換藝人與角色」，Pocamarket 的篩選是價格、類型、隱藏缺貨。
- 金庫卡和自由刊登分兩個頁籤（見「兩條交易線」）；自由刊登搜尋標題、團體、成員、專輯、版本，篩選團體和價格，排序按最新刊登和價格。
- 市場頁（`/market`）：關鍵字搜尋（團體、成員、專輯、版本、編號，多個詞全部命中）、團體 → 成員兩層切換（選項旁顯示數量）、類型、價格區間、只看在售、排序（最新入庫、價格高低；價格篩選和排序只算鏈上在售的卡）、每頁 12 張分頁。篩選狀態全部寫在網址查詢字串裡，可以分享，也能用瀏覽器返回。
- 導航列的搜尋框送到市場頁；首頁放最新入庫的 8 張和「看全部」入口，類型標籤直接連到篩選好的市場頁。
- 金庫頁按狀態分頁籤並可搜尋；圖鑑團體頁可按成員、類型篩選，並搜尋版本名稱。
- 金庫卡清單整站共用一份（`/api/vault/cards`，伺服器快取 30 秒），篩選在瀏覽器端完成；卡片多了之後改成伺服器端查詢資料庫，網址參數格式不變。

## 圖鑑與收藏冊

- 不交易的粉絲也有理由每天來：圖鑑收錄每個卡款（團體 × 專輯 × 成員 × 版本），可以標記「有」和「想要」，旁邊顯示在售數量和最低價；卡款有對應的金庫卡時用它的實拍照片。
- 收藏冊做成一本實體活頁卡冊：硬殼外框、中間三個活頁環，左右各一頁、每頁 3×3 透明卡套；翻頁時頁面以書脊為軸 3D 翻轉，窄螢幕一次一頁，也支援鍵盤左右鍵。另有鏈上卡、擔保訂單、收集進度和想要清單頁籤。學 Pocamarket 和 KOCA，收藏冊要登入才用；未登入時展示一本用金庫裡有照片的卡填好的樣例卡冊。
- 冊子裡有三種卡：錢包裡的金庫卡（買來的、開卡包抽到的、寄存的）、自己上鏈的卡、圖鑑標記「有」的卡款。前兩種跟著鏈上持有顯示；標記的卡款只是記錄，卡套裡畫虛線框、標「僅記錄」，和真卡一眼分開。卡套只顯示照片，點開是詳情：金庫卡的主按鈕進卡片頁，已刊登的收藏卡主按鈕進刊登頁，未刊登的在詳情裡刊登、改描述、寄進金庫。
- **整理收藏冊**：像實體卡冊一樣自己決定每張卡放在哪個卡套，可以留空卡套。點一張卡拿起、再點卡套放下（卡套有卡就互換），電腦上也能拖曳。鏈上的卡可以「拿出收藏冊」放進卡盒，之後放回；標記的卡款鏈上沒有，拿出就是刪掉標記。新到手的卡接在最後一張後面；賣掉的卡留下空卡套，買回來回到原位。擺法存在 `binder_layouts` 表（每個卡套的卡鍵和拿出冊子的卡鍵），規則在 `src/lib/binder-layout.ts`。頂部的張數、團體數、上鏈數只算冊子裡的卡。
- **收藏冊同步**：帳號資料（標記、想要、擺法）以伺服器為準，瀏覽器存一份副本並記著屬於哪個帳號。屬於帳號的副本只當快取：有還沒上傳成功的改動就以本機為準補傳，否則採用伺服器的版本，所以別的裝置刪掉的卡不會被舊副本合併回來；未登入時記的標記只在登入那一次合併進帳號。改動 0.6 秒內合併成一次整本上傳，一次只送一個請求，關頁時用 keepalive 送出未送的改動；伺服器在同一個交易裡整本覆蓋寫入。
- **自由上鏈**：用戶拍下卡片正反面（都必填，背面能看出版本和真偽線索），可以再補最多 6 張照片（一組卡的合照、卡角細節）；選來源、填團體和成員，標題、張數、出處名稱、版本選填，還可以寫一段描述（品相、入手經過、交換條件，最多 500 字，之後隨時能改），就加進收藏冊。加卡和刊登只存資料庫，不鑄造：擔保交易的收款、放款和抽成都在平台，不需要 NFT。想要這張卡的數位珍藏，綁了錢包的用戶可以在收藏冊**自己付費上鏈**（像 Getgems 由鑄造者付費）：伺服器組好鑄造交易，手續費和帳戶押金（約 0.003 SOL）由用戶錢包付，平台以集合更新權限者共同簽名；確認時核對 NFT 在收藏集合裡、持有人是這個錢包、元數據指向這張卡（`src/lib/server/funds.ts` 的 `buildUserMint`、`checkUserMint`）。上鏈的卡在擔保交易成交時由平台轉給買家、被查出假卡時在鏈上凍結；沒上鏈的卡這些步驟跳過。平台不墊付收藏卡的鑄造費。描述只存在資料庫，NFT 元數據即時讀取，改描述不用動鏈上。一則可以是一張卡，也可以是一組卡，學 KOCA 和粉絲在社群裡出卡的習慣。來源不只專輯：專輯、預購特典、幸運抽、簽售和視訊簽售、演唱會和見面會周邊、年曆、官方粉絲俱樂部禮包、快閃店、音樂節目和活動、品牌合作、其他。卡款不必在圖鑑裡，圖鑑和團體名錄只提供輸入建議；單張卡的名稱和圖鑑完全一致時自動關聯卡款。團體名錄（`src/lib/kpop-groups.ts`）收 122 個團體：參考 Wikidata（CC0）裡曲風為 K-pop、維基條目多的團體，團名用官方寫法，主流團附成員藝名（含已離隊成員，他們的小卡仍在流通）和別名（TXT、SNSD、(G)I-DLE），其餘團體的成員由用戶自填。Pocamarket 的藝人清單只在登入後的私有接口裡，不去抓。加卡和刊登都需要登入；自己上鏈要綁定錢包，沒有平台金鑰的環境不能上鏈。
- 用戶路徑：記錄收藏 → 自由上鏈 → 自由刊登，或寄卡入庫鑑定後走金庫交易。

## 兩條交易線

市場分成兩條線，對應 Pocamarket 的 Official 和 Used：

| | 金庫卡（`/card/[id]`） | 自由刊登（`/listing/[id]`） |
|---|---|---|
| 卡在哪 | Idolca 金庫 | 賣家手上 |
| 誰查驗 | Idolca 入庫時實物鑑定，通過才鑄造 | 沒人查驗，買家看到免責聲明 |
| NFT | 金庫集合的 Core NFT，`verification: authentic` | 收藏集合的 Core NFT，`verification: unverified` |
| 成交 | 鏈上託管程序原子交換，卡不動 | 擔保交易：買家付 USDT 進平台錢包，賣家寄卡，買家確認收貨後平台放款並用 PermanentTransferDelegate 把 NFT 轉給買家 |
| 提貨 | 銷毀 NFT 換實物 | 不適用，卡本來就在持有人手上 |

- 自由刊登就是給收藏 NFT 標價：可以在上鏈時直接刊登，也可以之後在收藏冊裡刊登、改價、下架。
- 市場頁用頁籤切換兩條線，網址參數 `lane=free`；自由刊登頁籤頂部和商品頁價格旁都放免責聲明。自由刊登的卡用賣家照片和「待驗證」標籤顯示，不加全息效果，和金庫卡一眼分得出來。

### 卡片 NFT 的鑑定狀態

兩條線是兩碼事，鑑定狀態也分開，只有平台能改，持有人改不了：

| 狀態 | 屬於 | 含義 |
|---|---|---|
| `unverified`（待驗證） | 收藏 NFT | 自由上鏈的卡一律是這個狀態，平台不查驗 |
| `fake`（假卡） | 收藏 NFT | 被檢舉或寄到金庫後查出是假卡；同時下架，之後不能再刊登 |
| `authentic`（真品） | 金庫 NFT | 金庫入庫鑑定通過才鑄造，所以金庫 NFT 一律是真品 |

- **收藏 NFT**：鑄造到獨立的「Idolca Collector」Core 集合，手續費由平台代付。錢包登入的用戶鑄到自己的錢包，郵箱帳號鑄到平台代管錢包。平台是集合的更新權限持有人，可以改寫名稱和屬性。屬性（Attributes 插件）：團體、成員、來源、張數、出處名稱、版本、`custody: self`、`verification`；元數據 JSON 由 `/api/meta/item/{id}` 提供，含所有照片。每個 NFT 自帶 PermanentFreezeDelegate 插件，平台可以單獨凍結假卡；集合帶 PermanentTransferDelegate 插件，自由刊登成交時由平台把 NFT 轉給買家。
- **寄進金庫**：持有人在收藏冊對自己上鏈的卡申請寄進金庫（要綁定錢包），申請後自動下架、不能再刊登，頁面給出參考編號和金庫收件地址（`NEXT_PUBLIC_VAULT_ADDRESS`），實物寄到前可以取消。後台收到實物後鑑定：真品就轉成金庫卡——照片和資料沿用，補上類型、外部評級、倉位，金庫 NFT 鑄到持有人的錢包，再銷毀原本的收藏 NFT（持有人不是平台時先用集合的 PermanentTransferDelegate 收回，同一筆交易裡銷毀）；先鑄後銷，銷毀失敗時重試只補做銷毀。不收但不是假卡就退回，清掉申請；假卡則退回並標成假卡。
- **標記假卡**：收藏 NFT 不銷毀。平台在同一筆交易裡把名稱改成「[FAKE] …」、屬性改成 `verification: fake`，並凍結 NFT，防止它被當作真卡轉賣；元數據 JSON 也同步顯示假卡說明，任何外部市場和錢包都看得到。標記不可由持有人移除，平台也不會在鏈上撤銷。
- 金庫的託管合約只接受金庫集合的資產，收藏 NFT 在鏈上就無法走金庫交易。
- 紀錄、刊登價格、NFT 地址和交易簽名存進 `collector_items` 表，照片存進 `media` 表。

## 金庫卡

- 金庫卡存在 `vault_cards` 表：編號（`IC-` 加六位流水號，印在卡套標籤上，和 NFT 屬性一致）、團體、成員、專輯、版本、類型、外部評級、品相說明、正反面照片、倉位、入庫日期、NFT 地址、寄存人。持有人、掛單價格和提貨狀態不存表，以鏈上為準。
- **評級一律記機構**：每個分數都連同評級機構、分數（1–10，可以有 .5）和鑑定編號一起記錄，三項缺一不收，機構清單在 `src/lib/grading.ts`。卡片頁、卡面、NFT 屬性都顯示成「PSA 10 · #編號」，PSA 和 CGC 的編號連到它們的公開查詢頁。沒記機構的舊分數不顯示。
  - 自家評級是 Idolca Grading，簡稱 IDG，鑑定編號就是金庫編號；卡片頁註明「Idolca 自家評級，非第三方機構」。
  - 第三方機構：PSA、CGC、BRG、Pocagrades。
  - 入庫時可以順便評級；已入庫的卡在後台「給金庫卡評級」評級、改評級或清掉評級，會同時改寫 NFT 屬性裡的評級三項（`/api/admin/vault/[id]/grade`）。已提貨的卡不能改。
  - 定位和取捨見 research.md 1.6。
- 入庫由後台完成，有兩個入口：直接入庫（上傳正反面，走同一條照片處理流程；平台自有的展示庫存也可以改用樣本照片，接口帶 `sample`（`src/lib/sample-credits.json` 的編號），署名頁自動列出作者和授權；填資料、選寄存人——填郵箱或錢包，NFT 鑄到他綁定的錢包，不填就是平台自有庫存），或把用戶寄進金庫的收藏卡轉成金庫卡（見「卡片 NFT 的鑑定狀態」）。兩者都由伺服器鑄造金庫 NFT 並寫入表。
- 提貨寄出時記下銷毀時間，卡移出金庫清單；鏈上已銷毀但表裡還沒記的（例如用別的工具提貨），讀鏈時自動補記。
- devnet 的金庫在資料庫第一次連線時寫入 2026 年 10 月在 devnet 鑄造的 19 張樣本卡（`src/lib/server/seed-devnet.ts`）；主網的金庫從空的開始。

## 提貨

- 持有人在卡片頁填收件地址（收件人、電話、地址、城市、郵遞區號、國家或地區），確認後錢包簽一筆交易：凍結 NFT、委託銷毀權、付運費。運費用 `NEXT_PUBLIC_REDEEM_FEE_USDT` 設定（預設 5 USDT，含追蹤號的國際掛號），伺服器按備註和金額對帳，沒付到的申請後台看得到但不能出貨。可寄送的國家或地區列在 `src/lib/shipping.ts`。
- 地址存在瀏覽器裡，下次自動帶入；伺服器上的地址在寄出 90 天後由排程清除，取消提貨時立即清除。
- 後台出貨時在同一筆交易裡解凍並銷毀 NFT；寄不到等情況由後台取消：解凍、交還凍結和銷毀委託、退運費。取消後持有人可以再次申請。

## 專輯銷量榜

- Pocamarket 和 KOCA 都沒有專輯銷量榜，這是差異化功能，目前只做看板（`/charts`）：Circle Chart 週專輯榜的當週前 10 名，顯示名次變化、專輯、藝人、發行商、本週銷量和累計銷量。
- 數據直接讀 Circle Chart 網頁本身用的接口（先從榜單頁讀出最新的年份和週次），只取名次和銷量這些事實數據，不取專輯封面；伺服器快取幾小時，對方每週更新一次。頁面標明來源並連回原榜單。Circle Chart 沒有公開的使用條款或官方接口，正式營運前改走授權渠道（例如 Chartmetric）或取得韓國音樂內容協會同意。
- 之後接「代購代拆」：用戶在 Idolca 預購專輯，平台向計入榜單的零售商購買並在首爾開封，小卡入庫，專輯計入銷量；上線前要先確認這種模式是否計入。

## 盲盒卡包（Mystery Pack）

- 參考 Pocamarket 的 Mystery Pack：低價買一包，有機會抽中高價卡；卡池有限，賣完提前結束；有即時抽卡播報。學 Courtyard，卡池裡每張都是金庫裡的實物：抽到的就是那張卡的金庫 NFT，從平台錢包轉進買家錢包。
- 卡包存在 `packs` 表（名稱、價格、每筆訂單最多開幾包、開賣和結束時間、包裝顏色），由後台建立；小卡池的卡包可以設成只能單抽。卡池是後台放進卡包的平台自有金庫卡，每張設等級（SSR、SR、R、N）和價值。價值決定期望價值和回購價。
- 機率不單獨設定，等於「該級剩餘張數 ÷ 卡池剩餘總數」，隨賣出即時變化；頁面公開每級剩餘張數、價值區間、單包期望價值和整個卡池（每張連到卡片頁）。
- **定價和返還率**：卡池是抽一張少一張，賣完時的利潤 = 張數 × 售價 − 卡池總價值，售價由後台自己定。返還率 = 剩下卡池的單包期望價值 ÷ 售價，有上限 `NEXT_PUBLIC_PACK_MAX_RTP`（預設 0.8）：
  - 每單下單前用剩下的卡池重算，超過上限就暫停販售，頁面顯示「補貨中」，補進便宜的卡或調高售價後恢復。這樣卡包不會賣虧，也沒人能等便宜的卡抽完再撿期望值高過售價的尾單。
  - 後台每個卡包顯示賣完時的返還率、預計利潤和剩餘卡池的返還率；頁面公開期望價值和返還率。
  - 卡的價值要參考實際成交行情，不能灌水：返還率和期望價值都由它算出，填高了等於誤導買家。
- **公平性（承諾—揭示）**：建立卡包時生成 32 位元組的隨機種子，開賣前只公開它的 SHA-256。第 n 抽的隨機數 r = HMAC-SHA256(種子, 付款交易簽名:n)；付款簽名由買家錢包產生，平台事先算不出來。抽中的位置 = floor(r 的前 12 位十六進位 ÷ 2^48 × 當時卡池張數)，卡池按編號排序後取那一張。卡包結束或抽完後公開種子，每一抽的付款簽名、序號、卡池張數、位置和 r 都在 `/api/packs/{id}/draws`，任何人都能重算（`src/lib/pack-draw.ts`）。
- 一次可開 1、5、10 包（不超過卡包的上限）：撕開卡包，逐張翻卡，SSR 有金色光圈。賣完的卡包留在列表和首頁，標「已售罄」，照樣能看卡池、抽卡紀錄和公平性核對。抽到的卡可以留在金庫、上架、即時回購或提貨。訂單先從待付款鎖成抽卡中，同一筆只抽一次；卡池在付款後不夠（或轉移失敗）時，沒交付的張數自動退款。
- 只對確認已滿 18 歲的帳號開放（第一次開包時確認一次），並按來源國家屏蔽（`PACKS_BLOCKED_COUNTRIES`，預設比利時和荷蘭，上線前由法務按營運地確認）。

## 卡片內頁

## 不放假數據

頁面上的數字只來自鏈上或自己的資料庫，沒有來源的就不顯示：沒有成交歷史就不畫價格走勢，沒有即時匯率就不顯示當地貨幣，沒有收藏功能的後端就不顯示按讚數。圖鑑卡款的在售數量和最低價由金庫卡的鏈上掛單加上自由刊登算出。金庫裡沒有卡時，首頁的最新入庫和卡包入口不顯示；沒有平台金鑰時不鑄造、不寫假的 NFT 地址。

## 上線主網

代碼不用改，按順序做：

1. 準備一個新的平台錢包（熱錢包，只放付手續費的 SOL 和擔保、卡包收款的週轉資金），和一個冷錢包當抽成收款錢包。
2. 用 `anchor deploy` 把託管程序部署到主網（程序升級權限之後轉給多簽）。
3. `NEXT_PUBLIC_SOLANA_CLUSTER=mainnet-beta` 下執行 `npm run chain:setup`（建兩個集合）和 `TREASURY_ADDRESS=<冷錢包> npm run chain:setup-market`（以官方 USDT 初始化託管程序），地址寫進 `src/lib/chain/mainnet-beta.json` 並提交。
4. Vercel 上建一個新的 Neon 資料庫，設 `NEXT_PUBLIC_SOLANA_CLUSTER=mainnet-beta`、`PLATFORM_SECRET_KEY`、`SOLANA_RPC_URL`（付費 RPC）、`NEXT_PUBLIC_SITE_URL`、`ADMIN_WALLETS`、`CRON_SECRET`、`NEXT_PUBLIC_CONTACT_EMAIL`、`NEXT_PUBLIC_VAULT_ADDRESS`、`NEXT_PUBLIC_REDEEM_FEE_USDT`、`PACKS_BLOCKED_COUNTRIES`。
5. 管理員登入後台，實物入庫、建立卡包。

營運上的待辦（法務、開放地區、運費報價、資金管理）見 [business.md](business.md)。

## 錢包交易流程

所有需要用戶簽名的動作都是同一個模式：伺服器組好交易（手續費付款人是用戶錢包，需要平台參與的部分由平台先簽）→ 瀏覽器錢包用 Wallet Standard 的 `solana:signAndSendTransaction` 簽名送出 → 伺服器等交易確認、更新狀態。前端不載入 Anchor，也不接觸平台金鑰。

| 流程 | 用戶簽什麼 | 平台做什麼 |
|---|---|---|
| 買金庫卡 | 託管程序的 `buy`：USDT 付給賣家和平台抽成，NFT 轉給買家 | — |
| 掛單、取消 | 託管程序的 `list` / `cancel` | — |
| 申請提貨 | 委託銷毀權、以平台為凍結代理凍結 NFT、付運費 | 對帳運費；出貨時在同一筆交易裡解凍並銷毀；取消時解凍、交還委託、退運費 |
| 自由刊登購買 | 把 USDT 轉進平台錢包，備註寫訂單編號 | 按備註和金額對帳後託管貨款，規則見下方「擔保交易」 |
| 開卡包 | 把 USDT 轉進平台錢包，備註寫訂單編號 | 對帳後抽卡，把抽到的金庫卡 NFT 轉給買家；沒交付的張數退款 |
| 即時回購 | 把 NFT 轉給平台 | 同一筆交易裡付 USDT（平台先簽），卡回到卡池 |

- **擔保交易**：
  - 買家確認收貨後，平台放款給賣家（扣 2.5%），並把 NFT 轉給買家；賣家沒綁錢包時貨款先暫存，綁定後補發。
  - 賣家付款後 7 天內沒標記寄出，自動全額退款，卡按原價重新上架。
  - 寄出後 14 天內買家沒確認也沒申訴，自動放款。買家「回報問題」後訂單轉為申訴中，暫停自動放款，由後台退款或放款。
  - 同一件商品被兩人同時付款時，後到的自動退款。
  - 逾時處理在用戶打開訂單列表時順帶執行，每日排程也會執行。退款和放款前先把訂單鎖成「退款中」「放款中」，同一筆不會被處理兩次；鏈上轉帳失敗時解鎖回原狀態。
  - 期限和抽成定義在 `src/lib/policy.ts`，服務條款直接引用；測試時可用 `ESCROW_SHIP_DAYS`、`ESCROW_CONFIRM_DAYS` 縮短期限（單位天，可以是小數）。
- **錢包綁定**：郵箱帳號可以在帳號選單裡綁定錢包（同樣是簽一段文字證明持有），之後買賣都用這個錢包；錢包登入的帳號本身就有錢包。
- **測試幣**：前台不發測試幣。接口 `/api/chain/faucet` 只在 devnet 開放，給登入的錢包發 0.02 SOL 和 500 測試 USDT（平台是測試 USDT 的鑄幣權限持有人），每個帳號 10 分鐘一次；主網沒有這個接口。
- **鏈上即時狀態**：金庫卡的持有人、掛單價格、是否提貨中直接讀鏈（一次批量讀資產和掛單帳戶，伺服器快取 10 秒），市場、金庫頁、卡片頁和收藏冊都以它為準；已提貨銷毀的卡移出金庫和市場。

## 合規要點

- 服務條款（`/terms`）和隱私權政策（`/privacy`）：註冊和錢包登入框下方註明繼續即同意。條款裡的抽成、擔保期限、回購比例、運費和地址保留天數直接讀平台規則，改規則時條款跟著變。聯絡郵箱用 `NEXT_PUBLIC_CONTACT_EMAIL` 設定。
- 盲盒卡包和回購有賭博屬性：機率按卡池剩餘張數即時公開，同時公開單包期望價值和可重算的抽卡紀錄；限 18 歲以上，按地區屏蔽；已開的卡包不退款。
- 個人資料只收服務需要的：收件地址寄出 90 天後刪除，不寫上鏈；IP 只用於頻率限制，國家只用於卡包地區判斷。
- 結算用穩定幣：Arc 通道收 Circle 發行的 USDC，錢落在發行方自己的鏈上；每條通道收哪種幣是設定，接受的幣可以照各地法規調整。
- 穩定幣出入金涉及反洗錢：提現到外部錢包超過一定金額時做 KYC。
- 偶像肖像有 IP 風險：上線後 NFT 和卡片頁只用入庫實物的掃描圖，不拿偶像照片做營銷素材。devnet 的樣本卡用 CC BY 授權照片，在 `/credits` 頁署名，不用於廣告投放。

## 測試

- 單元測試（`npm test`，vitest）：卡包機率和期望價值、抽卡公平性的重算、收件地址驗證、收藏冊擺法、八種語言的鍵和參數一致、程式碼裡寫死的每個翻譯鍵都存在。
- 端到端測試（`e2e/`）對著跑起來的網站和 devnet 執行，每次都是真實交易，會入庫測試卡和建測試卡包，所以網站要用獨立的測試資料庫啟動（`PGLITE_DIR=.data/pglite-e2e`）：`test:e2e:vault`（入庫、卡包、公平性核對、回購、提貨和取消、收藏卡轉金庫卡）、`test:e2e:escrow`（擔保交易的逾時退款、申訴、自動放款、後台放款）、`test:e2e:ui`（無頭 Chrome 注入 Wallet Standard 測試錢包，點完主要流程並截圖）、`test:e2e:binder`（收藏冊同步：拿出冊子的標記被刪、別的裝置刪掉的卡不會回來、未送出的改動會補傳）。管理員錢包金鑰檔用 `E2E_ADMIN_KEYPAIR` 指定，地址要在網站的 `ADMIN_WALLETS` 裡；測試照片在執行時生成。
- GitHub Actions 每次推送跑 lint、型別檢查、單元測試和正式構建。

## 卡面圖片

- 沒有實拍圖的卡，卡面由 `src/lib/card-art.ts` 用 canvas 生成佔位圖。
- 卡片資料帶 `image` 時，3D 卡和列表卡改用實拍圖，載入失敗退回佔位圖。
- 所有照片走同一條處理流程（`src/lib/server/media.ts`）：伺服器端驗證確實是圖片，裁成 55:85、660×1020 的 JPEG，存兩份——未加浮水印的原圖留給鑑定，加了浮水印的展示圖對外提供。上傳的一組正反面只要有一張不合格就整組拒絕。
- 浮水印學 Pocamarket：半透明的白色 idolca 文字標誌斜 30° 平鋪滿整張圖，帶極淡的黑色描影，深淺背景上都看得見；裁掉一角也去不掉。正反面用同一套處理，和平台統一卡背的平鋪標誌一致。標誌用字形輪廓繪製，不依賴伺服器上的字型。
- devnet 樣本卡的照片是維基共享資源上 CC BY 授權的偶像照片，倉庫裡只記來源網址和裁切位置（`src/lib/sample-credits.json`）。某張樣本照第一次被請求時，伺服器從維基共享資源抓圖，走上面的流程入庫，之後直接從資料庫讀。圖片按網址長期快取，所以樣本照的 id 帶處理版本號（`src/lib/sample-image.ts` 的 `SAMPLE_REV`）：裁切或浮水印一改就把版本號加一，伺服器重新生成，瀏覽器和 CDN 也不會繼續用舊圖。作者和授權由 `/credits` 頁公開署名，只列金庫卡實際用到的照片。
