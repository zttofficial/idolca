# 技術選型

## 產品定位

面向海外 K-pop 粉絲的小卡倉儲交易平台：實物入庫鑑定，成交時卡留在倉庫、所有權即時轉移，用戶隨時可以合併提貨。MVP 是 Web2 產品，用戶不接觸錢包和鏈。

## 已採用

| 層 | 選擇 | 理由 |
|---|---|---|
| 框架 | Next.js 16（App Router）+ React 19 + TypeScript | 市場頁和卡片頁需要 SSR 和 SEO；前後端同一個倉庫 |
| 樣式 | Tailwind CSS v4 | 開發快；深色、光暈這類視覺效果用 CSS 變數集中管理 |
| 3D 卡片 | three.js + React Three Fiber + drei | 首頁主視覺：真實厚度和圓角的小卡，可拖動旋轉、翻到背面 |
| 全息效果 | 自寫的 GLSL shader（3D 卡）、CSS 混合模式（列表卡） | 3D 卡只有一張，用 WebGL；列表卡很多，用純 CSS 保證性能 |
| 包管理 | npm | 本機已有，不另裝 |

## 計劃採用（尚未安裝）

| 層 | 選擇 | 理由 |
|---|---|---|
| 資料庫 | PostgreSQL（Supabase 或 Neon）+ Drizzle ORM | 訂單、所有權、庫存都是強一致的關係型數據 |
| 認證 | Supabase Auth 或 Better Auth | 郵箱、Google、Apple 登入；不做錢包登入 |
| 支付 | Stripe Connect | 平台代收款、驗貨後放款給賣家，正好對應擔保交易 |
| 圖片存儲 | Cloudflare R2 | 卡片正反面高清掃描圖；出口流量免費 |
| 多語言 | next-intl | 繁中、簡中、英文起步，之後加泰文、印尼文 |
| 部署 | Vercel | 和 Next.js 配套，零運維 |

## 所有權與鏈

- 所有權記錄在 PostgreSQL：卡片表加上一張只追加不修改的轉移流水表（誰、何時、從誰到誰、成交價）。
- 每張卡有唯一編號（如 `PV-000128`），對應倉庫裡的一張實物。
- 流水表的結構要能直接映射成鏈上的轉移記錄。將來需要接入加密資金（開放外部交易、可驗證的抽卡隨機數、倉庫存貨證明）時，再選鏈把流水錨定上去；在那之前不引入錢包。

## 卡面圖片

- 目前的卡面是 `src/lib/card-art.ts` 用 canvas 程序化生成的佔位圖，團體和成員都是虛構的。
- 接入真實卡片後，3D 卡和列表卡都改用入庫時拍攝的正反面掃描圖作貼圖，渲染代碼不用改。
- 偶像肖像有 IP 風險：只展示用戶寄存的實物掃描圖，不拿偶像照片做營銷素材。
