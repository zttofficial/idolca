# 技術選型

## 產品定位

K-pop 小卡的鏈上倉儲交易平台：實物入庫鑑定，每張卡在 Solana 上對應一個 NFT；成交時卡留在倉庫，NFT 在鏈上轉移；持有人隨時可以銷毀 NFT，換取實物寄出。價格標 USD，用 Solana 上的 USDT、USDC 或 Arc 上的 USDC 結算（Arc 見 [arc.md](arc.md)）。

用戶有兩種登入方式，登入框裡並列，互不衝突：
- **加密用戶**：用 MetaMask、Phantom、Solflare、Backpack 等支援 Solana 的瀏覽器錢包簽名登入，上鏈的卡直接進自己的錢包。
- **粉絲**：用郵箱和密碼註冊，不需要錢包就能加卡；驗證信箱後才能刊登。要付款或把卡做成數位珍藏時才設定錢包：在 Idolca 建一個收藏錢包（不用安裝、不用助記詞），或綁定自己的錢包。

這樣首頁和產品都是 Web3 的，但不把不懂加密的粉絲擋在門外。

| 全息效果 | 自寫的 GLSL shader（3D 卡）、CSS 混合模式（列表卡） | 3D 卡只有一張，用 WebGL；列表卡很多，用純 CSS 保證性能 |

## Web3

| 層 | 選擇 | 理由 |
|---|---|---|
| 鏈 | **Solana** | 卡牌 RWA 的主戰場（約 63% 的代幣化卡牌交易在 Solana）；Magic Eden、Tensor、Jupiter 都能直接交易；手續費不到 1 美分 |
| 網路切換 | `NEXT_PUBLIC_SOLANA_CLUSTER`（`devnet` / `mainnet-beta`） | 每個網路的公開地址（平台錢包、兩個集合、託管程序、結算代幣）各存一份 `src/lib/chain/<cluster>.json`，換網路只改這個變數，不改代碼。水龍頭、測試幣標籤只在 devnet 出現 |
| 帳號 | 自建：郵箱 + 密碼，或錢包簽名 | 帳號存在自己的資料庫，不依賴第三方登入服務。密碼用 Node 內建 scrypt 加鹽雜湊；錢包登入是 Sign In With Solana 的簡化版：伺服器發一段帶一次性隨機數的訊息（5 分鐘有效、用過即作廢），錢包簽名後伺服器用 ed25519 驗簽，地址第一次出現就建帳號。兩種方式都換成同一種會話：令牌放 httpOnly cookie，資料庫只存它的 SHA-256。郵箱帳號見「信箱驗證和密碼」。Google、Apple 登入暫不做 |
| 錢包 | Wallet Standard（`@wallet-standard/app`） | 直接偵測瀏覽器裡的 MetaMask、Phantom、Solflare、Backpack 等 Solana 錢包，不經過第三方連接服務；一個都沒有時連到 Solana 官方的錢包列表 |
| 收藏錢包 | **Privy** 嵌入式錢包（`@privy-io/react-auth`，`NEXT_PUBLIC_PRIVY_APP_ID`） | 給沒有錢包的郵箱帳號：私鑰由 Privy 分片保管，平台拿不到。Privy 按月活用戶收費，所以只在用戶要建錢包、簽名或加值時才載入 SDK、登入 Privy，平常瀏覽和刊登都不碰（`src/lib/privy/bridge.ts`）。登入用 Privy 寄到用戶已驗證信箱的 6 位數驗證碼；換成由我們發 JWT、免輸入驗證碼的 custom auth 要 Privy 的付費方案，改的只有登入那一段。錢包註冊進 Wallet Standard，綁定和簽名跟外部錢包走同一套；Privy 自己的簽名確認視窗關掉（`showWalletUIs: false`），付款面板是唯一的確認。Privy 後台的 Allowed origins 放正式網域和 `http://localhost:3000`，預覽部署用不了收藏錢包 |
| 卡片 NFT | **Metaplex Core**，金庫卡和自由上鏈的收藏卡各一個集合，都帶平台可改的 `verification` 鑑定狀態 | 一張卡一個帳戶，鑄造成本約 0.003 SOL；Attributes 插件存屬性（編號、團體、成員、專輯、版本、類型、評級機構、分數、鑑定編號、庫位、入庫日期），FreezeDelegate、BurnDelegate 插件管提貨，集合上的 Royalties 插件收二級市場版稅 |
| 計價與結算 | 標 **USD**；Solana 上 **USDT 和 USDC** 都收（SPL、6 位小數、1:1），Arc 上收 USDC | 前台只標 USD、不換算當地貨幣（見「首頁」）。付款時錢包裡哪種夠就用哪種，兩種都夠時用餘額多的，都不夠時直接回「餘額不足」，不讓錢包簽注定失敗的交易（`src/lib/coins.ts`、`vault-chain.ts` 的 `pickCoin`）。退款和放款用原來付的那種；Arc 付款的訂單在 Solana 上用 USDC 放款。主網用 Tether 的 USDT 和 Circle 的 USDC，devnet 兩種都用平台自鑄的測試幣 |
| 鏈上程序 | Anchor 1.x（Rust） | 自寫一個最小的託管程序：賣家掛單時 NFT 轉進以資產地址為種子的 PDA，買家付款後原子交換，平台抽成在同一筆交易內扣除；拍賣時 NFT 和出價都鎖在拍賣帳戶裡，結標時一次交換（見「拍賣」）。只接受平台集合的資產和 Config 登記的 USDT、USDC（`set_mints` 可以換），抽成上限 10%。價格以美元計，買家用哪種付都行，賣家收到買家付的那種。建立帳戶的指令都有獨立的 `payer` 付租金並記在帳戶上（`rent_payer`），關閉時租金退回它 |
| 手續費和帳戶租金 | 平台錢包代付 | 用戶簽的每筆交易都由平台錢包當手續費付款人並先簽名，託管程序和 Core 的帳戶租金也由平台付，用戶錢包只要有穩定幣，不用準備 SOL（`vault-chain.ts` 的 `forUser`）。組好交易先模擬，會失敗的不交給錢包，因為失敗的交易照樣扣手續費；組金庫卡交易每個帳號每小時最多 60 次，防止反覆掛單、取消消耗平台的 SOL |
| 鏈上數據讀取 | Solana RPC（`SOLANA_RPC_URL`） | 金庫卡清單在資料庫，持有人、掛單、凍結狀態按清單批量讀鏈（`getMultipleAccounts`，RPC 一次最多 100 個帳戶，超過就分批）；主網換付費 RPC，避免公共節點限流 |
| 抽卡隨機數 | 承諾—揭示（HMAC-SHA256） | 不依賴第三方 VRF：開賣前公開種子的雜湊，每抽的隨機數由種子和買家錢包產生的付款簽名決定，結束後公開種子，任何人都能重算（見「盲盒卡包」） |

### 鏈上流程

| 動作 | 鏈上發生什麼 |
|---|---|
| 入庫 | 實物鑑定通過後，後台建立金庫卡並鑄造 Core NFT 給寄存人的錢包；平台自有庫存（卡包卡池）鑄給平台錢包 |
| 掛單、成交 | NFT 進託管程序；買家付 USDT 或 USDC，NFT 和款項在同一筆交易裡交換；取消掛單時 NFT 退回賣家 |
| 外部交易 | Core NFT 可以在 Magic Eden、Tensor 直接買賣，不經過平台 |
| 提貨 | 持有人在一筆交易裡：把銷毀權委託給平台、以平台為凍結代理立即凍結、付運費（備註寫卡片 id）。寄出時平台在同一筆交易裡解凍並銷毀。取消時平台解凍、交還兩個委託並退運費 |
| 開盲盒 | 買家付 USDT 或 USDC 進平台錢包；平台對帳後按承諾的種子從卡池抽卡，把抽到的那張金庫卡 NFT 從平台錢包轉給買家 |
| 即時回購 | 平台按卡在卡包裡的價值的 70% 付款（用開卡包時付的那種幣）：持有人把 NFT 轉給平台、平台付款，兩步在同一筆交易裡（平台先簽付款，持有人簽轉移）；卡回到卡池 |

### 存貨證明

- 公開的金庫頁（`/vault`）：列出每個編號對應的 NFT 地址、持有人、狀態（在庫、掛單中、提貨中）和入庫日期，持有人和狀態直接讀鏈；點編號進卡片頁看正反面照片。
- 未銷毀的 NFT 總數必須等於倉庫實物數量：提貨中的卡還在倉庫裡，NFT 凍結但未銷毀；寄出時才銷毀。正式營運後定期公布盤點結果。
- 平台不持有永久凍結權或永久銷毀權，只有持有人主動申請提貨時才臨時委託給平台。

### 不做

- **不發平台代幣。** 代幣會讓產品被看成炒幣，加重粉絲反感和監管風險；先證明交易本身成立。

## 後端與基礎設施

| 層 | 選擇 | 理由 |
|---|---|---|
| 資料庫 | PostgreSQL + Drizzle ORM | 線上用 Neon（在 Vercel Marketplace 一鍵接入，連線字串自動填入 `DATABASE_URL`；接入時設了變數前綴也認得，會找以 `_DATABASE_URL` 結尾的變數）；本機開發沒有 `DATABASE_URL` 時用 PGlite（嵌入式 Postgres，資料在 `.data/`）。表結構由 `BOOTSTRAP_SQL` 在第一次連線時建立和補欄位，全部可重複執行。必須一起生效的多條寫入走 `atomic()`（`src/lib/server/db.ts`）：Neon 的 HTTP 驅動不支援互動式交易，用 batch（整批在同一個交易裡），PGlite 用一般交易。每個網路用自己的資料庫：devnet 的帳號、卡片和訂單不帶到主網 |
| 圖片存儲 | PostgreSQL `media` 表 | 卡片正反面照片和資料一起存進資料庫，不另接存儲服務，也不放進代碼倉庫。經 `/api/media/{id}` 提供並長期快取，Vercel 的 CDN 擋掉重複請求。照片量大到撐不住資料庫容量時，只換 `src/lib/server/media.ts` 的實現，遷到 Cloudflare R2 這類對象存儲，網址格式不變 |
| 排程 | Vercel Cron 每天呼叫 `/api/cron/daily`（`CRON_SECRET` 保護） | 處理逾時的擔保訂單（含提醒還沒填收件地址的買家）、清除過期的收件地址、刪掉過期的會話、登入挑戰碼和郵件連結 |
| 頻率限制 | 資料庫計數（`rate_limits` 表） | 不另接服務，多個伺服器實例共用：登入每個 IP 15 分鐘 20 次，註冊每小時 10 個，忘記密碼 15 分鐘 5 次（同一個信箱每小時 3 封），重寄驗證信每個帳號每小時 5 封，錢包挑戰碼 10 分鐘 60 次，自由上鏈每個帳號每小時 30 張 |
| 法幣入金 | Privy 的入金彈窗（`useDepositFunds`：Stripe、MoonPay；完成 Meld 的 KYB 後支援 50 多種法幣） | 收藏錢包用信用卡、Apple Pay 買 Solana 上的 USDC。入金服務不支援測試網，帳號選單的「加值」只在主網出現 |
| 產品分析 | PostHog（歐盟機房，`posthog-js`） | 在 `src/instrumentation-client.ts` 初始化，只在正式構建且設了 `NEXT_PUBLIC_POSTHOG_KEY` 時啟用（Vercel 上只設在 Production，預覽部署、本機和端到端測試不送）。不用 cookie 也不寫瀏覽器儲存空間（`cookieless_mode: "always"`，PostHog 專案設定裡要開啟），所以不需要同意彈窗；代價是跨天認不出同一個人、沒有操作回放，要這些得改成先徵求同意。頁面瀏覽和來源自動記；關鍵動作用 `src/lib/analytics.ts` 的 `track` 記：註冊、登入、綁錢包、加卡、做成數位珍藏、上架（一口價或拍賣）、購買、出價、開卡包。付款類的事件在付款方式面板付款成功時統一記，帶上交易線、付款方式和金額。事件不帶郵箱、錢包地址和收件地址。選它而不是 Vercel Analytics，是因為要看轉換漏斗和自訂事件（Vercel 的自訂事件要付費方案） |
| 部署 | Vercel（前端）、Anchor 程序部署到 Solana | — |
| 包管理 | npm | 本機已有，不另裝 |

## 後台與權限

- 後台（`/admin`）只給管理員帳號：資料庫裡 `role` 是 `admin` 的帳號（`npm run admin:grant -- <郵箱或錢包>` 授予），或錢包地址在 `ADMIN_WALLETS` 裡的帳號。環境變數只認錢包，因為錢包登入有簽名證明，比郵箱難冒用。管理員在帳號選單裡看得到後台入口，所有後台接口在伺服器端按會話檢查。
- 後台處理：入庫（拍正反面、填卡片資料和倉位，鑄造金庫 NFT；或把寄進金庫的收藏卡轉成金庫卡）、盲盒卡包（建卡包、把平台自有卡放進卡池並設等級和價值）、擔保交易（看買家的收件地址和賣家填的物流單號，退款或放款，申訴中的排最前面）、提貨（看收件地址和運費是否到帳、填物流單號出貨銷毀、更正單號、取消並退運費）、標記假卡。

## 市場瀏覽

- 參考兩個競品：KOCA 主打「切換藝人與角色」，Pocamarket 的篩選是價格、類型、隱藏缺貨。
- 金庫卡和自由刊登分兩個頁籤（見「兩條交易線」）；自由刊登搜尋標題、團體、成員、專輯、版本，篩選團體和價格，排序按最新刊登和價格。
- 市場頁（`/market`）：關鍵字搜尋（團體、成員、專輯、版本、編號，多個詞全部命中）、團體 → 成員兩層切換（選項旁顯示數量）、類型、價格區間、只看在售、排序（最新入庫、價格高低；價格篩選和排序只算鏈上在售的卡）、每頁 12 張分頁。篩選狀態全部寫在網址查詢字串裡，可以分享，也能用瀏覽器返回。
- 導航列的搜尋框送到市場頁；首頁放最新入庫的 8 張和「看全部」入口，類型標籤直接連到篩選好的市場頁。
- 金庫頁按狀態分頁籤並可搜尋；圖鑑團體頁可按成員、類型篩選，並搜尋版本名稱。
- 金庫卡清單和在售的自由刊登整站各共用一份（`/api/vault/cards`、`/api/listings`，伺服器快取 30 秒）。市場頁在伺服器上直接讀這兩份資料、照網址的篩選條件輸出第一屏的卡片和連結，讓搜尋引擎看得到商品，再經 `MarketDataProvider` 交給瀏覽器端的共用資料，不重複請求；鏈上的即時價格和掛單仍由瀏覽器補上。篩選在瀏覽器端完成；卡片多了之後改成伺服器端查詢資料庫，網址參數格式不變。

## 圖鑑與收藏冊

- 不交易的粉絲也有理由每天來：圖鑑收錄每個卡款（團體 × 專輯 × 成員 × 版本），可以標記「有」和「想要」，旁邊顯示在售數量和最低價；卡款有對應的金庫卡時用它的實拍照片。
- 收藏冊做成一本實體活頁卡冊：硬殼外框、中間三個活頁環，左右各一頁、每頁 3×3 透明卡套；翻頁時頁面以書脊為軸 3D 翻轉，窄螢幕一次一頁，也支援鍵盤左右鍵。另有擔保訂單、收集進度和想要清單頁籤；錢包裡的金庫卡就在卡冊裡，不另開頁籤（舊網址 `?tab=onchain` 落回卡冊）。學 Pocamarket 和 KOCA，收藏冊要登入才用；未登入時展示一本用金庫裡有照片的卡填好的樣例卡冊。
- 冊子裡有三種卡：錢包裡的金庫卡（買來的、開卡包抽到的、寄存的）、自己上鏈的卡、圖鑑標記「有」的卡款。前兩種跟著鏈上持有顯示；標記的卡款只是記錄，卡套裡畫虛線框、標「僅記錄」，和真卡一眼分開。卡套只顯示照片，點開是詳情：金庫卡的詳情顯示狀態（掛單價、拍賣出價、提貨中或在庫），在這裡上架、改價、下架或進卡片頁；已刊登的收藏卡主按鈕進刊登頁，未刊登的在詳情裡刊登、改描述、寄進金庫。沒綁錢包時卡冊上方提示綁定後金庫卡會自動放進來。
- **篩選卡冊**：「全部／在售中」之外，可以搜尋關鍵字（團體、成員、專輯、版本、收藏卡標題、金庫卡編號，多個詞全部命中），再選團體 → 成員；選項只列冊子裡實際有的團體和成員，附符合關鍵字的張數。團體、成員不分大小寫和前後空白比對，自己上鏈時填的寫法不一致也歸在一起。三種卡都能篩；「全部」只篩冊子裡的卡（拿出收藏冊的不算），「在售中」篩所有在售的卡。結果照擺放順序排成連續卡套，用同一本書顯示，換條件回到第一頁。條件寫在網址（`?filter=listed&q=&group=&member=`）。團體和成員放在卡冊上方的篩選面板裡，預設收起、團體和成員都排成標籤，卡冊保持整個寬度；收起時按鈕標出生效的條件數，結果數前寫出目前的團體 › 成員，旁邊可以清除。搜尋框、篩選按鈕和團體 → 成員是市場同一套元件（`src/components/market/CardFilters.tsx`；市場放在左側欄），比對和計數在 `src/lib/facets.ts`，收藏冊的條件在 `src/lib/binder-filter.ts`。有搜尋或篩選、或在「在售中」時不能整理收藏冊：篩選結果是擠在一起的卡套，換位置對不上整本冊子的卡套。Pocamarket 的 Collect Book 只是買到的卡的存放處，沒有公開的團體、成員篩選（App Store 評論抱怨想要清單不能按團體、成員篩）；KOCA 主打切換藝人與角色，所以照市場的做法給卡冊加上。
- **整理收藏冊**：像實體卡冊一樣自己決定每張卡放在哪個卡套，可以留空卡套。點一張卡拿起、再點卡套放下（卡套有卡就互換），電腦上也能拖曳。鏈上的卡可以「拿出收藏冊」放進卡盒，之後放回；標記的卡款鏈上沒有，拿出就是刪掉標記。新到手的卡接在最後一張後面；賣掉的卡留下空卡套，買回來回到原位。擺法存在 `binder_layouts` 表（每個卡套的卡鍵和拿出冊子的卡鍵），規則在 `src/lib/binder-layout.ts`，一本最多記 10000 個卡鍵。頂部的張數、團體數、上鏈數只算冊子裡的卡。
- **大量卡片**：冊子要撐得住幾千張卡。卡冊只畫攤開的那一兩頁；卡的內容和擺法分開快取，只在資料變了才重算，整理時只改擺法；卡款對金庫卡的照片用索引查（`templateCard`），不逐張掃。整理畫面每頁和卡盒每段捲到附近才畫卡面，拿起、放下只重畫有變動的頁。
- **收藏冊同步**：帳號資料（標記、想要、擺法）以伺服器為準，瀏覽器存一份副本並記著屬於哪個帳號。屬於帳號的副本只當快取：有還沒上傳成功的改動就以本機為準補傳，否則採用伺服器的版本，所以別的裝置刪掉的卡不會被舊副本合併回來；未登入時記的標記只在登入那一次合併進帳號。改動 0.6 秒內合併成一次整本上傳，一次只送一個請求，關頁時用 keepalive 送出未送的改動；伺服器在同一個交易裡整本覆蓋寫入。
- **自由上鏈**：用戶拍下卡片正反面（都必填，背面能看出版本和真偽線索），可以再補最多 6 張照片（一組卡的合照、卡角細節）；選來源、填團體和成員，標題、張數、出處名稱、版本選填，還可以寫一段描述（品相、入手經過、交換條件，最多 500 字，之後隨時能改），就加進收藏冊。加卡和刊登只存資料庫，不鑄造：擔保交易的收款、放款和抽成都在平台，不需要 NFT。想要這張卡的數位珍藏，有錢包的用戶可以在收藏冊**做成數位珍藏**：付鑄造費 `MINT_FEE_USD`（0.5 USD，USDT 或 USDC），NFT 帳戶的押金和手續費（約 0.003 SOL）由平台付；伺服器組好鑄造交易，平台以付款人和集合更新權限者的身分先簽，鑄造費和鑄造在同一筆交易裡；確認時核對 NFT 在收藏集合裡、持有人是這個錢包、元數據指向這張卡（`src/lib/server/funds.ts` 的 `buildUserMint`、`checkUserMint`）。上鏈的卡在擔保交易成交時由平台轉給買家、被查出假卡時在鏈上凍結；沒上鏈的卡這些步驟跳過。描述只存在資料庫，NFT 元數據即時讀取，改描述不用動鏈上。一則可以是一張卡，也可以是一組卡，學 KOCA 和粉絲在社群裡出卡的習慣。來源不只專輯：專輯、預購特典、幸運抽、簽售和視訊簽售、演唱會和見面會周邊、年曆、官方粉絲俱樂部禮包、快閃店、音樂節目和活動、品牌合作、其他。卡款不必在圖鑑裡，圖鑑和團體名錄只提供輸入建議；單張卡的名稱和圖鑑完全一致時自動關聯卡款。團體名錄（`src/lib/kpop-groups.ts`）收 122 個團體：參考 Wikidata（CC0）裡曲風為 K-pop、維基條目多的團體，團名用官方寫法，主流團附成員藝名（含已離隊成員，他們的小卡仍在流通）和別名（TXT、SNSD、(G)I-DLE），其餘團體的成員由用戶自填。Pocamarket 的藝人清單只在登入後的私有接口裡，不去抓。加卡和刊登都需要登入；自己上鏈要綁定錢包，沒有平台金鑰的環境不能上鏈。
- 用戶路徑：記錄收藏 → 自由上鏈 → 自由刊登，或寄卡入庫鑑定後走金庫交易。

## 兩條交易線

市場分成兩條線，對應 Pocamarket 的 Official 和 Used：

| | 金庫卡（`/card/[id]`） | 自由刊登（`/listing/[id]`） |
|---|---|---|
| 卡在哪 | Idolca 金庫 | 賣家手上 |
| 誰查驗 | Idolca 入庫時實物鑑定，通過才鑄造 | 沒人查驗，買家看到免責聲明 |
| NFT | 金庫集合的 Core NFT，`verification: authentic` | 可選：持有人付鑄造費、做成收藏集合的 Core NFT，`verification: unverified` |
| 成交 | 鏈上託管程序原子交換，卡不動 | 擔保交易：買家付 USDT 或 USDC 進平台錢包，賣家寄卡，買家確認收貨後平台放款；卡做成了 NFT 時，平台再用 PermanentTransferDelegate 把它轉給買家 |
| 提貨 | 銷毀 NFT 換實物 | 不適用，卡本來就在持有人手上 |

- 自由刊登就是給收藏冊裡的卡標價：加卡時直接刊登，或之後在收藏冊裡刊登、改價、下架。兩條線的卡都可以改用拍賣出售，見「拍賣」。
- 市場頁用頁籤切換兩條線，網址參數 `lane=free`；自由刊登頁籤頂部和商品頁價格旁都放免責聲明。自由刊登的卡用賣家照片和「待驗證」標籤顯示，不加全息效果，和金庫卡一眼分得出來。
- 市場只列在售的自由刊登。刊登頁的網址永久有效：成交、下架、拍賣結束後仍打得開，顯示已售出（成交價和日期）、交易中、已轉成金庫卡（連到卡片頁）或目前沒有在售，加上交易紀錄（刊登、開拍、流拍、成交，成交連到 NFT 轉移或付款交易）；不在售時不顯示賣家卡片，也不讓搜尋引擎收錄。收藏冊的訂單、站內通知和 NFT 元數據都連到這頁。只在收藏冊裡、沒成交過也沒做成數位珍藏的卡不公開。

### 卡片 NFT 的鑑定狀態

兩條線是兩碼事，鑑定狀態也分開，只有平台能改，持有人改不了：

| 狀態 | 屬於 | 含義 |
|---|---|---|
| `unverified`（待驗證） | 收藏 NFT | 自由上鏈的卡一律是這個狀態，平台不查驗 |
| `fake`（假卡） | 收藏 NFT | 被檢舉或寄到金庫後查出是假卡；同時下架，之後不能再刊登 |
| `authentic`（真品） | 金庫 NFT | 金庫入庫鑑定通過才鑄造，所以金庫 NFT 一律是真品 |

- **收藏 NFT**：鑄造到獨立的「Idolca Collector」Core 集合，持有人付鑄造費、平台代付押金，鑄到他的錢包（見「圖鑑與收藏冊」的自由上鏈）。平台是集合的更新權限持有人，可以改寫名稱和屬性。屬性（Attributes 插件）：團體、成員、來源、張數、出處名稱、版本、`custody: self`、`verification`；元數據 JSON 由 `/api/meta/item/{id}` 提供，含所有照片。每個 NFT 自帶 PermanentFreezeDelegate 插件，平台可以單獨凍結假卡；集合帶 PermanentTransferDelegate 插件，自由刊登成交時由平台把 NFT 轉給買家。
- **寄進金庫**：持有人在收藏冊對自己上鏈的卡申請寄進金庫（要綁定錢包），申請時選寄到哪個金庫：兩個金庫的收件地址都列出來（`NEXT_PUBLIC_VAULT_ADDRESS_YVR`、`NEXT_PUBLIC_VAULT_ADDRESS_CKG`），按持有人上次填的收件國家（沒有就看瀏覽器語言的地區）建議一個：北美（加拿大、美國、墨西哥）建議溫哥華，賣家寄國內或北美件就能入庫；其他地區一律建議重慶，因為重慶寄到任何地方的提貨運費都比溫哥華低；選擇記在 `collector_items.vault_target`。申請後自動下架、不能再刊登，頁面給出參考編號和所選金庫的收件地址，實物寄到前可以取消。後台收到實物後鑑定：真品就轉成金庫卡——照片和資料沿用，補上收到它的金庫（預設帶入持有人選的）、類型、外部評級、倉位，金庫 NFT 鑄到持有人的錢包，再銷毀原本的收藏 NFT（持有人不是平台時先用集合的 PermanentTransferDelegate 收回，同一筆交易裡銷毀）；先鑄後銷，銷毀失敗時重試只補做銷毀。不收但不是假卡就退回，清掉申請；假卡則退回並標成假卡。
- **標記假卡**：收藏 NFT 不銷毀。平台在同一筆交易裡把名稱改成「[FAKE] …」、屬性改成 `verification: fake`，並凍結 NFT，防止它被當作真卡轉賣；元數據 JSON 也同步顯示假卡說明，任何外部市場和錢包都看得到。標記不可由持有人移除，平台也不會在鏈上撤銷。
- 金庫的託管合約只接受金庫集合的資產，收藏 NFT 在鏈上就無法走金庫交易。
- 紀錄、刊登價格、NFT 地址和交易簽名存進 `collector_items` 表，照片存進 `media` 表。

## 拍賣

兩條交易線都能拍賣。賣家在上架時選「一口價」或「拍賣」，拍賣中的卡在原來的刊登頁（`/listing/[id]`）或卡片頁（`/card/[id]`）顯示拍賣面板：目前出價、倒數、保底價有沒有達到、出價紀錄。和 KOCA 最大的不同是**出價就鎖款**：每次出價先付全額，被超過時自動退回，得標者早就付了錢，不會有人棄標。KOCA 是得標後 24 小時內結帳，棄標只能停權，錢包帳號換個新錢包就繞過了。

| | 金庫卡 | 自由刊登 |
|---|---|---|
| 狀態存在哪 | 鏈上：託管程序的 Auction 帳戶（以資產地址為種子），NFT 在拍賣期間屬於它 | 資料庫：`auctions`、`bids` 表 |
| 出價 | 一筆 Solana 交易：USDT 或 USDC 轉進拍賣帳戶存那種幣的代幣帳戶（開拍時兩種各開一個），同一個指令用前一口的幣種退回前一位最高出價者 | 付款進平台錢包（Solana 或 Arc），對帳後才算出價；被超過的那口由平台退款 |
| 結標 | `settle_auction`，任何人都能呼叫：NFT 給得標者，款項（得標那口的幣種）扣手續費給賣家，同一筆交易 | 得標款直接變成一張已付款的擔保訂單（`orders.auction_id`），照擔保交易的期限寄出、確認、放款 |
| 付款通道 | 只有 Solana，卡和錢原子交換 | Solana 或 Arc |
| 流拍 | NFT 退回賣家，最高出價退回 | 卡回到收藏冊（未刊登），最高出價退回 |

- 金庫卡拍賣在鏈上的拍賣設定（AuctionConfig）建好後才開放：`/api/chain/state` 回報 `auctions`，沒有時上架只能選一口價。
- **規則**（兩條線一樣，數字在 `src/lib/policy.ts`）：起標價至少 10 USD；拍賣 1、3、5 或 7 天；保底價可選，金額不公開，只顯示有沒有達到。
- **加價**：第一口是起標價；之後 50 USD 以下每口至少加 1 USD，50 到 200 USD 至少加 5 USD，200 USD 以上至少加 2.5%（無條件進位）。規則在 `src/lib/auction.ts` 的 `minNextBid`，和程序的 `min_next_bid` 用同一組測試數字。
- **防搶標**：截止前 5 分鐘內有新出價，截止時間延到這口出價後 5 分鐘。
- 出價不能撤回；第一口出價之前賣家可以取消，之後不行。賣家不能對自己的拍賣出價，目前最高的出價者不能再加價。
- **出價紀錄公開**，大家看得到是真有人在搶。自由刊登的出價者用代號（出價者 1、2…，按第一次出價的順序），只列被接受過的出價。金庫卡的每一口都是鏈上交易，從拍賣帳戶的交易解出 `BidPlaced` 事件，從新往舊讀到這場的 `AuctionCreated` 為止（拍賣帳戶按卡固定，每場共用），列出錢包地址、金額、時間和交易連結，誰都能到區塊瀏覽器核對；接口 `/api/chain/bids/[cardId]` 帶上鏈上記的出價數，數字變了就不用快取。
- 拍賣中的卡不能一口價刊登、申請提貨或寄進金庫；開拍時已經一口價刊登的卡會先下架。自由刊登的卡在拍賣中被標成假卡時，拍賣作廢，最高出價退回。
- 手續費 4%，開拍時記在拍賣上，之後改費率不影響進行中的拍賣；從賣家所得扣，買家只付出價（理由見 business.md「拍賣」）。
- **自由刊登的出價時限**：出價建單後要在 2 分鐘內付款確認（Arc 授權的有效期也是 2 分鐘）；確認時拍賣已截止、或別人先出了更高的價，這口不被接受、全額退款。截止後再等 2 分鐘才結標，讓截止前送出的付款來得及確認；寫入最高出價時有樂觀鎖，並要求截止時間還在這 2 分鐘內，所以結標開始後不可能再接受出價。結標的訂單編號由拍賣決定（`auction-<id>`），重複結標不會建兩張。
- **及時結標**：Vercel 的排程一天只跑一次，所以靠請求順便處理：讀拍賣狀態（`/api/auctions/[id]`，拍賣頁每 5 秒讀一次）和自由刊登列表時，有到期的拍賣或待退款的出價就在回應後（`after()`）結標、退款；讀金庫卡鏈上狀態（`/api/chain/state`）時，有已截止的拍賣就由平台錢包送出 `settle_auction`。每日排程是保底。
- **退款**：被超過、沒被接受、流拍和作廢的出價先記成 `outbid`，退款時鎖成 `refunding`，鏈上轉帳失敗就放回去等下次；標成最高、但已經不是拍賣最高出價的那口（中途中斷留下的）也會被修正後退款。
- 代碼：`src/lib/server/auctions.ts`（自由刊登）、`src/lib/server/vault-chain.ts` 的拍賣函式（金庫卡）、`src/components/auction/`（拍賣面板）、`src/components/market/ListingControl.tsx`（上架時選方式）；接口 `/api/items/[id]/auction`、`/api/bids`、`/api/bids/[id]/confirm`、`/api/auctions/[id]`，金庫卡的動作走 `/api/chain/vault/tx`（`auction`、`bid`、`cancelAuction`）。

## 手續費和規則的數字

| 規則 | 存在哪 | 怎麼改 | 進行中的交易 |
|---|---|---|---|
| 金庫卡一口價成交抽成（2.5%） | `src/lib/policy.ts` 的 `FEE_BPS`，同步到鏈上 Config | 改常數後重跑 `npm run chain:setup-market`（呼叫 `update_config`），不用重新部署程序 | 成交時才讀，所有掛單立即適用新費率 |
| 金庫卡拍賣（手續費、起標價下限、時長範圍、延長時間） | `policy.ts`，同步到鏈上 AuctionConfig | 同上（呼叫 `update_auction_config`） | 手續費開拍時記在拍賣帳戶上，進行中的不受影響 |
| 擔保交易抽成、擔保期限、自由刊登的拍賣規則、地址保留天數 | `policy.ts` | 改常數後推送部署 | 抽成在建單和開拍時記在訂單、拍賣上，已成立的不受影響 |

- 服務條款直接讀這些常數，改了條款跟著變。鏈上抽成上限 10%，超過會被程序拒絕。
- 全站調費率只是改數字。限時或按用戶的折扣要加代碼：自由刊登和拍賣的手續費在建單、開拍時算，加一個折扣規則就行；金庫卡一口價的抽成是鏈上的全域設定，按用戶打折要改程序，或成交後由平台返還差額。

## 金庫卡

- 金庫有兩個（`src/lib/vaults.ts`，伺服器和頁面共用）：溫哥華（YVR，自營）和重慶（CKG，合作倉，成本低）。每張卡只放在一個金庫，提貨從那裡寄出、運費按它算。卡片頁顯示「存放於某某金庫」，金庫頁可以按金庫分開看，NFT 屬性和元數據也記著金庫。
- 金庫卡存在 `vault_cards` 表：編號（`IC-` 加六位流水號，印在卡套標籤上，和 NFT 屬性一致）、團體、成員、專輯、版本、類型、外部評級、品相說明、正反面照片、所在金庫（`vault`，分兩個金庫之前入庫的卡在溫哥華）、倉位、入庫日期、NFT 地址、寄存人。持有人、掛單價格和提貨狀態不存表，以鏈上為準。
- **評級一律記機構**：每個分數都連同評級機構、分數（1–10，可以有 .5）和鑑定編號一起記錄，三項缺一不收，機構清單在 `src/lib/grading.ts`。卡片頁、卡面、NFT 屬性都顯示成「PSA 10 · #編號」，PSA 和 CGC 的編號連到它們的公開查詢頁。沒記機構的舊分數不顯示。
  - 自家評級是 Idolca Grading，簡稱 IDG，鑑定編號就是金庫編號；卡片頁註明「Idolca 自家評級，非第三方機構」。
  - 第三方機構：PSA、CGC、BRG、Pocagrades。
  - 入庫時可以順便評級；已入庫的卡在後台「給金庫卡評級」評級、改評級或清掉評級，會同時改寫 NFT 屬性裡的評級三項（`/api/admin/vault/[id]/grade`）。已提貨的卡不能改。
  - 定位和取捨見 research.md 1.6。
- 入庫由後台完成，有兩個入口：直接入庫（上傳正反面，走同一條照片處理流程；平台自有的展示庫存也可以改用樣本照片，接口帶 `sample`（`src/lib/sample-credits.json` 的編號），署名頁自動列出作者和授權；填資料、選金庫、選寄存人——填郵箱或錢包，NFT 鑄到他綁定的錢包，不填就是平台自有庫存），或把用戶寄進金庫的收藏卡轉成金庫卡（見「卡片 NFT 的鑑定狀態」）。兩者都由伺服器鑄造金庫 NFT 並寫入表。
- 提貨寄出時記下銷毀時間，卡移出金庫清單；鏈上已銷毀但表裡還沒記的（例如用別的工具提貨），讀鏈時自動補記。
- devnet 的金庫在資料庫第一次連線時寫入 2026 年 10 月在 devnet 鑄造的 19 張樣本卡（`src/lib/server/seed-devnet.ts`）；主網的金庫從空的開始。

## 提貨

- 持有人在卡片頁填收件地址（收件人、電話、地址、城市、州或省、郵遞區號、國家或地區；寄加拿大時省份必填，從 13 個省和地區的代碼選），確認後錢包簽一筆交易：凍結 NFT、委託銷毀權、付運費（加拿大境內另加 GST/HST）。卡從它所在的金庫寄出，表單的國家只列那個金庫寄得到的；預填的地址在別的國家時不能送出，表單說明這個金庫寄不到。
- 運費按（金庫，目的地）計價，選好國家後表單即時顯示運費，送出按鈕顯示要付的總額；表單附連結到公開運費表 `/shipping`。運費 =（郵資 + 包材）× 1.15，按那個金庫的匯率換成美元後無條件進位到 0.5 USD；15% 是吸收匯率、燃油附加費和郵局調價的緩衝，不是利潤。規則在 `src/lib/policy.ts`，計算在 `src/lib/shipping.ts`，各金庫的郵資、包材和匯率在 `src/lib/rates/`，瀏覽器、伺服器和服務條款共用。一張卡裝卡套、硬殼卡套和氣泡袋，實重和體積重都在 100g 內，按 100g 一檔計。報價在 2026-10-14 查詢，來源網址寫在郵資表的註解裡；郵局調價、燃油附加費大幅變動或匯率偏離時改那裡。
  - **溫哥華**（`rates/yvr.ts`，加幣）：國外寄加拿大郵政 Tracked Packet（有追蹤），取官方〈Solutions for Small Business〉價目表（2026-09-07 版）0.1kg 一檔，加國際小包燃油附加費（每週調整，2026-10-12 那週 25.25%）。加拿大國內寄掛號信（Lettermail 非標準件 100g 內 2.61 + Registered Mail 13.15，全國同價，不收燃油附加費）；國內包裹最低一檔 0.5kg 按起訖地區 9.68 到 20.80，再加 48% 燃油附加費，比掛號信貴。Tracked Packet 不送達泰國、印尼、越南、菲律賓、澳門，出貨又必須有物流單號，所以溫哥華的卡不寄這幾個地方。包材按 401 Games 的卡套加硬殼卡套和 Uline 的氣泡袋均攤，每張 0.46 加幣。匯率用加拿大央行的日均匯率（1 USD = 1.4263 CAD）。
  - **重慶**（`rates/ckg.ts`，人民幣）：國外和香港寄中國郵政國際 e 郵寶（有追蹤），台灣和澳門 e 郵寶不到，改寄 e 特快；價格取中國郵政協議客戶門戶從重慶寄 100g 的報價。中國大陸國內寄韻達普快件，全國按最遠的新疆 20 元一個價。包材按 1688 的起批價均攤，每張 0.27 元。匯率用中國外匯交易中心的人民幣匯率中間價（1 USD = 6.7249 CNY）。
  - 各地的運費見公開運費表 `/shipping`，數字由同一份郵資表現算，這裡不另列。重慶寄到任何地方都比溫哥華便宜，連寄美國和加拿大也是；溫哥華的優勢在北美賣家入庫方便。
  - **GST/HST**：溫哥華寄加拿大境內，運費另收收件省份的 GST/HST（安大略 13%，新斯科細亞 14%，新不倫瑞克、紐芬蘭與拉布拉多、愛德華王子島 15%，其他 5%；CRA 稅率表，`src/lib/rates/ca-tax.ts`）。稅 = 運費 × 稅率，四捨五入到分，總額 = 運費 + 稅。國際件不收：溫哥華寄國外、重慶寄任何地方都是零稅率的寄送服務。只收聯邦稅，不收省稅。稅率表在 `redeemTaxRate`，金額在 `redeemCharge`（`src/lib/shipping.ts`）；依據見 business.md「稅」。表單把運費和稅分成兩行，還沒選省份時說明選好省份後顯示稅額。
  - 伺服器不收前端傳的金額：組交易時從資料庫讀卡所在的金庫，用 `redeemCharge` 按（金庫，收件國家，省份）算出運費加稅放進轉帳指令，那個金庫不寄的地方直接拒絕。確認時用回報的收件地址再算一次，鏈上付的金額要剛好等於總額（同時核對付款人和備註）才標記已付，運費和稅分別存在 `redemptions.fee_cents`、`tax_cents`。兩次的國家或省份對不上就當沒付，後台看得到但不能出貨，只能取消。
- 公開運費表 `/shipping`（`src/app/[locale]/shipping/page.tsx`，表格是 `src/components/shipping/RateTable.tsx`），八種語言，頁尾和服務條款連過去：說明提貨是什麼、從卡所在的金庫寄出、全程有追蹤號碼；列出兩個金庫的寄法、寄送範圍和採用匯率；每個國家或地區一列，兩個金庫各一欄（那個金庫不寄的顯示「不寄」），國名按頁面語言用 `Intl.DisplayNames` 顯示，可以搜尋、按國名或任一金庫的運費排序，只有三欄，手機上不用橫向捲動。加拿大那一列和表下註明溫哥華寄國內另收 GST/HST。頁尾說明計價方式和兩個金庫的報價來源和查詢日期（`rates/yvr.ts`、`ckg.ts` 匯出的 `*_SOURCES`、`*_QUOTED_ON`）。金額全部用 `redeemFeeUsd` 現算，加稅說明的金庫按 `country === "CA"` 從金庫清單取，頁面沒有寫死的數字，整頁靜態產生。參考 Pocamarket 的運費表（每個國家一列、各寄法一欄、不支援的寫 Not supported），另外加上排序、計價方式和報價來源。
- 收件地址表單和擔保交易共用，預填上一次填過的地址（見「擔保交易」）；加拿大的省份必填這條也一起適用，伺服器的 `parseAddress` 擋掉缺省份或代碼不對的地址；伺服器上的地址在寄出 90 天後由排程清除，取消提貨時立即清除。
- 後台的提貨列表標出每張卡從哪個金庫寄出，以及運費和稅。出貨時要填物流單號（物流商預設卡所在金庫的郵政：溫哥華是加拿大郵政，重慶是中國郵政；元件和擔保交易共用，見「擔保交易」的物流單號），在同一筆交易裡解凍並銷毀 NFT，單號存在 `redemptions.tracking_carrier`、`tracking_number`，同時發站內通知給申請人。申請人在卡片頁看得到寄出日期和單號（`/api/redemptions/[cardId]`，只回給申請的帳號或申請時的錢包）。後台可以更正單號，更正後再通知一次。寄不到等情況由後台取消：解凍、交還凍結和銷毀委託、退運費和稅。取消後持有人可以再次申請。

- 數據直接讀 Circle Chart 網頁本身用的接口（先從榜單頁讀出最新的年份和週次），只取名次和銷量這些事實數據，不取專輯封面；伺服器快取幾小時，對方每週更新一次。頁面標明來源並連回原榜單。Circle Chart 沒有公開的使用條款或官方接口，正式營運前改走授權渠道（例如 Chartmetric）或取得韓國音樂內容協會同意。

## 盲盒卡包（Mystery Pack）

- 參考 Pocamarket 的 Mystery Pack：低價買一包，有機會抽中高價卡；卡池有限，賣完提前結束；有即時抽卡播報。學 Courtyard，卡池裡每張都是金庫裡的實物：抽到的就是那張卡的金庫 NFT，從平台錢包轉進買家錢包。
- 卡包存在 `packs` 表（名稱、價格、每筆訂單最多開幾包、開賣和結束時間、包裝顏色），由後台建立；小卡池的卡包可以設成只能單抽。卡池是後台放進卡包的平台自有金庫卡，每張設等級（SSR、SR、R、N）和價值。價值決定期望價值和回購價。
- 機率不單獨設定，等於「該級剩餘張數 ÷ 卡池剩餘總數」，隨賣出即時變化；頁面公開每級剩餘張數、價值區間、單包期望價值和整個卡池（每張連到卡片頁）。
- **定價和返還率**：卡池是抽一張少一張，賣完時的利潤 = 張數 × 售價 − 卡池總價值，售價由後台自己定。返還率 = 剩下卡池的單包期望價值 ÷ 售價，有上限 `NEXT_PUBLIC_PACK_MAX_RTP`（預設 0.8）：
  - 每單下單前用剩下的卡池重算，超過上限就暫停販售，頁面顯示「補貨中」，補進便宜的卡或調高售價後恢復。這樣卡包不會賣虧，也沒人能等便宜的卡抽完再撿期望值高過售價的尾單。
  - 後台每個卡包顯示賣完時的返還率、預計利潤和剩餘卡池的返還率；頁面公開期望價值和返還率。
  - 卡的價值要參考實際成交行情，不能灌水：返還率和期望價值都由它算出，填高了等於誤導買家。
- **公平性（承諾—揭示）**：建立卡包時生成 32 位元組的隨機種子，開賣前只公開它的 SHA-256。第 n 抽的隨機數 r = HMAC-SHA256(種子, 付款簽名:n)。付款簽名是買家產生、平台事先算不出來的：Solana 付款用買家錢包在付款交易裡的簽名（交易編號是付手續費的平台的簽名，平台算得出來，不能用），Arc 付款用買家的授權簽名。抽中的位置 = floor(r 的前 12 位十六進位 ÷ 2^48 × 當時卡池張數)，卡池按編號排序後取那一張。卡包結束或抽完後公開種子，每一抽的付款簽名、序號、卡池張數、位置和 r 都在 `/api/packs/{id}/draws`，任何人都能重算（`src/lib/pack-draw.ts`）。
- 一次可開 1、5、10 包（不超過卡包的上限）：撕開卡包，逐張翻卡，SSR 有金色光圈。賣完的卡包留在列表和首頁，標「已售罄」，照樣能看卡池、抽卡紀錄和公平性核對。抽到的卡可以留在金庫、上架、即時回購或提貨。訂單先從待付款鎖成抽卡中，同一筆只抽一次；卡池在付款後不夠（或轉移失敗）時，沒交付的張數自動退款。
- 只對確認已滿 18 歲的帳號開放（第一次開包時確認一次），並按來源國家屏蔽（`PACKS_BLOCKED_COUNTRIES`，預設比利時和荷蘭，上線前由法務按營運地確認）。

## 卡片內頁

- 學 Courtyard，只放四樣：照片（正面、背面、3D）、購買區、卡片資訊、鏈上紀錄。
- 購買區的價格是託管程序裡的掛單價，沒掛單就顯示「目前未出售」；按鈕按鏈上狀態給出能做的事（購買、取消自己的掛單、掛單或申請提貨）。
- 卡片資訊是鑄造時寫進 NFT 屬性的資料（編號、團體、成員、專輯、版本、類型、評級、品相、入庫日期、庫位），附 NFT 和集合的 Solscan 連結。
- 鏈上紀錄每次直接讀鏈：取這個資產的交易簽名，按交易日誌分類成鑄造、掛單、成交、取消掛單、開拍、流拍、取消拍賣、申請提貨、出貨銷毀、轉手；價格、買賣雙方從託管程序的事件資料解出（拍賣結標有得標者算成交）。伺服器快取 20 秒。

## 不放假數據

頁面上的數字只來自鏈上或自己的資料庫，沒有來源的就不顯示：沒有成交歷史就不畫價格走勢，沒有即時匯率就不顯示當地貨幣，沒有收藏功能的後端就不顯示按讚數。圖鑑卡款的在售數量和最低價由金庫卡的鏈上掛單加上自由刊登算出。金庫裡沒有卡時，首頁的最新入庫和卡包入口不顯示；沒有平台金鑰時不鑄造、不寫假的 NFT 地址。

## 上線主網

代碼不用改，按順序做：

1. 準備一個新的平台錢包（熱錢包，放代付手續費和帳戶租金的 SOL，以及 USDT、USDC 的週轉資金），和一個冷錢包當抽成收款錢包。
2. 用 `anchor deploy` 把託管程序部署到主網（程序升級權限之後轉給多簽）。
3. `NEXT_PUBLIC_SOLANA_CLUSTER=mainnet-beta` 下執行 `npm run chain:setup`（建兩個集合）和 `TREASURY_ADDRESS=<冷錢包> npm run chain:setup-market`（以官方 USDT 和 USDC 初始化託管程序，按 `policy.ts` 寫入抽成和拍賣設定），地址寫進 `src/lib/chain/mainnet-beta.json` 並提交。
4. Vercel 上建一個新的 Neon 資料庫，設 `NEXT_PUBLIC_SOLANA_CLUSTER=mainnet-beta`、`PLATFORM_SECRET_KEY`、`SOLANA_RPC_URL`（付費 RPC）、`NEXT_PUBLIC_SITE_URL`、`ADMIN_WALLETS`、`CRON_SECRET`、`NEXT_PUBLIC_CONTACT_EMAIL`、`NEXT_PUBLIC_VAULT_ADDRESS_YVR`、`NEXT_PUBLIC_VAULT_ADDRESS_CKG`、`PACKS_BLOCKED_COUNTRIES`。
5. 管理員登入後台，實物入庫、建立卡包。

營運上的待辦（法務、開放地區、物流契約、資金管理）見 [business.md](business.md)。

## 錢包交易流程

所有需要用戶簽名的動作都是同一個模式：伺服器組好交易（手續費付款人是平台錢包，平台先簽）→ 瀏覽器錢包用 Wallet Standard 的 `solana:signAndSendTransaction` 補上自己的簽名送出 → 伺服器等交易確認、更新狀態。交易編號是第一個簽名，也就是平台的，前端直接從交易裡讀，不用錢包回傳的簽名。前端不載入 Anchor，也不接觸平台金鑰。

| 流程 | 用戶簽什麼 | 平台做什麼 |
|---|---|---|
| 買金庫卡 | 託管程序的 `buy`：USDT 或 USDC 付給賣家和平台抽成，NFT 轉給買家 | — |
| 掛單、取消 | 託管程序的 `list` / `cancel` | — |
| 金庫卡開拍、取消拍賣 | 託管程序的 `create_auction` / `cancel_auction` | — |
| 金庫卡出價 | 託管程序的 `bid`：USDT 或 USDC 轉進拍賣帳戶，前一位的出價同時用原幣退回 | 截止後送出 `settle_auction` 結標 |
| 自由刊登出價 | 把 USDT 或 USDC 轉進平台錢包，備註寫出價編號（或在 Arc 上簽 USDC 授權） | 對帳後更新最高出價，退回被超過的出價；結標時得標款轉成擔保訂單 |
| 申請提貨 | 委託銷毀權、以平台為凍結代理凍結 NFT、付運費 | 對帳運費；出貨時在同一筆交易裡解凍並銷毀；取消時解凍、交還委託、退運費 |
| 自由刊登購買 | 把 USDT 或 USDC 轉進平台錢包，備註寫訂單編號 | 按備註和金額對帳後託管貨款，規則見下方「擔保交易」 |
| 開卡包 | 把 USDT 或 USDC 轉進平台錢包，備註寫訂單編號 | 對帳後抽卡，把抽到的金庫卡 NFT 轉給買家；沒交付的張數退款 |
| 即時回購 | 把 NFT 轉給平台 | 同一筆交易裡付貨款（平台先簽），卡回到卡池 |

- **擔保交易**：
  - 買家付款後商品下架，卡在放款前還在賣家的收藏冊裡：詳情標出「已賣出」和訂單狀態、連到訂單頁，訂單結束前不能再刊登、拍賣或寄進金庫。買賣雙方的紀錄都在收藏冊的「訂單」頁籤，每筆連到刊登頁。
  - 買家確認收貨後，平台放款給賣家（扣 2.5%），並把 NFT 轉給買家；賣家沒綁錢包時貨款先暫存，綁定後補發。
  - **收件地址**：付款前就要有收件地址。一口價購買時隨建單送出；自由刊登的拍賣在這場第一次出價時填（存在 `bids.shipping_address`，同一場再出價沿用），得標時寫進擔保訂單，這場所有出價上的地址同時清掉，取消、作廢的拍賣由排程清。所以付了款的訂單都帶著地址，賣家馬上能寄，買家不能靠拖著不填地址佔住一張卡；只有早期沒收地址的訂單要在「訂單」頁籤補填。買家寄出前都可以在「訂單」頁籤改地址。表單和提貨共用（`src/components/shipping/AddressDialog.tsx`，欄位和驗證在 `src/lib/shipping.ts`），預填買家上一次填過的地址（擔保訂單或提貨取較新的，`/api/account/address`），沒有再用瀏覽器存的。地址存在 `orders.shipping_address`，只在這筆訂單的買家、賣家和後台的訂單列表裡出現，刊登頁和公開接口不讀；訂單結束（完成、退款、取消）或建單沒付款 90 天後由排程清除。學 KOCA（下單時選賣貨便取貨門市）和一般電商，付款前就收地址，賣家收到付款通知時就能寄。
  - 買家寄出前可以修改地址，每次填寫或修改都通知賣家。賣家的訂單顯示地址（附複製按鈕），沒有地址時顯示「等買家填寫收件地址」、不能標記寄出；標記寄出時帶上他看到的地址填寫時間（`address_at`），買家剛好改過就被擋下，要看過新地址再寄。
  - **物流單號**：標記寄出時必填物流單號，物流商從清單選（加拿大郵政、中國郵政、韻達、韓國郵政、CJ、韓進、樂天、便利店宅配、日本郵便、中華郵政、台灣超商寄件、順豐、USPS、DHL、FedEx、UPS），清單外的選「其他」。單號去掉空白和連字號、只收英數字 6 到 40 位；郵政的國際郵件單號（UPU S10 格式）核對檢查碼，擋下抄錯一位的（`src/lib/tracking.ts`）。單號存在 `orders.tracking_carrier`、`tracking_number`，和地址一樣只給買家、賣家和後台看：買家在「訂單」頁籤看得到、能複製，物流商有公開查詢頁時附查詢連結；寄出通知帶單號；後台的訂單列表也顯示，申訴時用。寄出後到買家確認或申訴前，賣家可以更正單號，每次更正都通知買家。輸入和顯示的元件和提貨共用（`src/components/shipping/Tracking.tsx`）。單號是必填而不是選填：擔保交易靠它處理「沒收到」的申訴，沒有單號的平信不適合擔保交易。
  - 賣家要在付款和買家填好地址兩者較晚的時間起 7 天內標記寄出（`src/lib/escrow.ts`），否則買家可以取消、逾時處理也會自動全額退款；一口價的卡按原價重新上架（早期存進來、低於 1 分的價格除外，只回到收藏冊），拍賣得標的卡回到賣家的收藏冊。
  - 沒有地址的已付款訂單（只剩早期的）沒有寄出期限。買家付款後 7 天內沒填地址（`ESCROW_ADDRESS_DAYS`），逾時處理自動取消並全額退款，卡照上面的規則重新上架或回到收藏冊。付款 2 天後先提醒買家一次，訂單頁對買賣雙方寫出填地址的期限，後台看得到「買家還沒填收件地址」。
  - 不設罰款：佔住卡的前提是先把全額付進託管，付款時地址也已經在了，沒有不花成本的拖延方式。
  - 寄出後 14 天內買家沒確認也沒申訴，自動放款。買家「回報問題」後訂單轉為申訴中，暫停自動放款，由後台退款或放款。
  - 同一件商品被兩人同時付款時，後到的自動退款。
  - 逾時處理在用戶打開訂單列表時順帶執行，每日排程也會執行。退款和放款前先把訂單鎖成「退款中」「放款中」，同一筆不會被處理兩次；鏈上轉帳失敗時解鎖回原狀態。
  - 期限和抽成定義在 `src/lib/policy.ts`，服務條款直接引用；測試時可用 `ESCROW_SHIP_DAYS`、`ESCROW_CONFIRM_DAYS` 縮短期限（單位天，可以是小數）。
- **信箱驗證和密碼**：
  - 寄信用 Resend 的 HTTP 接口（`src/lib/server/mail.ts`，不裝 SDK），寄件人 `EMAIL_FROM`，預設 `Idolca <noreply@idolca.trade>`。信用帳號當時的介面語言寫，版型共用一個（`src/lib/server/email-auth.ts`）。本機沒設 `RESEND_API_KEY` 時信寫進 `.data/outbox.jsonl`；正式環境沒設就報錯。
  - 註冊後直接登入並寄驗證信，彈窗提示去收信。沒驗證的郵箱帳號可以加卡、整理收藏冊，不能刊登（一口價或拍賣）和綁定錢包，所以也買不了；加卡、上架和帳號選單在這些地方顯示同一塊提示，附「重寄驗證信」（每個帳號每小時 5 封）。錢包登入的帳號沒有信箱，不受限制。
  - 連結是一次性令牌，資料庫只存 SHA-256，並記下寄出時的信箱：驗證連結 24 小時有效，重設連結 1 小時；寄了新的同類連結，舊的作廢。頁面打開後才用 POST 送出令牌，信箱的連結掃描器 GET 網址不會把它用掉。驗證不要求登入，常見的是手機開信、電腦用網站。正式環境的連結一律指向 `NEXT_PUBLIC_SITE_URL`，不信請求的 Host。
  - 忘記密碼：不管信箱有沒有帳號都回一樣的結果；每個 IP 15 分鐘 5 次，同一個信箱每小時 3 封。重設成功即證明持有信箱，順帶標成已驗證；其他裝置全部登出，這台直接登入。被人搶先用自己信箱註冊時，真正的主人也是靠重設密碼拿回帳號。
  - 改密碼在帳號選單，要先輸入目前的密碼；改完其他裝置登出。
- **錢包**：郵箱帳號驗證信箱後，在帳號選單或任何要付款的地方「設定錢包」：建立收藏錢包，或綁定自己的錢包。兩者都要簽一段文字證明持有，綁定時記下錢包種類（`users.wallet_kind`），之後買賣都用這個錢包。一個錢包只屬於一個帳號：要綁的錢包之前登入過、自動建了一個沒有信箱的帳號時，簽名已證明是同一個人，綁定時把那個帳號的卡、訂單、拍賣、出價、收藏冊和通知併進郵箱帳號，再刪掉它（`src/lib/server/account-merge.ts`）；錢包已在另一個郵箱帳號上就拒絕。收藏錢包要簽名時，這個頁面還沒登入 Privy 就先登入；換了裝置或 Privy 登入過期時要輸入驗證碼，驗證碼視窗疊在付款面板上面。錢包登入的帳號本身就有錢包。
- **測試幣**：前台不發測試幣。接口 `/api/chain/faucet` 只在 devnet 開放，給登入的錢包發 0.02 SOL 和兩種測試幣各 500（平台是測試幣的鑄幣權限持有人），每個帳號 10 分鐘一次；主網沒有這個接口。
- **鏈上即時狀態**：金庫卡的持有人、掛單價格、拍賣、是否提貨中直接讀鏈（一次批量讀資產、掛單和拍賣帳戶，伺服器快取 10 秒），市場、金庫頁、卡片頁和收藏冊都以它為準；已提貨銷毀的卡移出金庫和市場。
- **站內通知**：頁首的通知鈴，登入後每分鐘和切回分頁時讀一次，有未讀就顯示數字；打開列表就全部標成已讀，點一則跳到對應的卡片、刊登或訂單頁。只做站內，不寄信（Resend 按量計費）。通知在伺服器處理那件事的地方寫入（`src/lib/server/notifications.ts`），寫入失敗只記日誌、不影響交易；同一件事用 key 去重，重複回報或排程重跑不會多發；90 天後由每日排程刪除。
  - 拍賣：賣家收到有人出價、拍出、流拍；出價者收到被超過、得標、流拍或作廢（款項退回）。
  - 擔保訂單：賣家收到賣出（要在期限內寄出）、買家填好或修改收件地址、放款（沒綁錢包時提示設定錢包）、退款、買家申訴；買家收到提醒填收件地址（付款 2 天後還沒填）、寄出（帶物流單號）、賣家更正單號、退款。
  - 提貨：寄出和後台更正單號時通知申請人，帶物流單號、連到卡片頁。
  - 金庫卡：出價和一口價成交是用戶錢包送出的交易，回報確認（`/api/chain/vault/confirm`）後讀那筆交易的事件發通知，卡和錢包都從事件讀，被超過的人從 `bid` 指令的 `prev_bidder` 帳戶讀；結標由平台送出，送出後直接通知。錢包沒有對應的帳號就不通知。送出交易後不回報確認的人（不經網站頁面操作），那一口的出價和被超過通知不會發，結標通知不受影響。

## 合規要點

- 服務條款（`/terms`）和隱私權政策（`/privacy`）：註冊和錢包登入框下方註明繼續即同意。條款裡的抽成、擔保期限、回購比例、運費和地址保留天數直接讀平台規則，改規則時條款跟著變。聯絡郵箱用 `NEXT_PUBLIC_CONTACT_EMAIL` 設定。
- 盲盒卡包和回購有賭博屬性：機率按卡池剩餘張數即時公開，同時公開單包期望價值和可重算的抽卡紀錄；限 18 歲以上，按地區屏蔽；已開的卡包不退款。
- 個人資料只收服務需要的：收件地址和物流單號在提貨寄出或擔保訂單結束 90 天後刪除，不寫上鏈，擔保訂單的地址只給該筆的賣家和後台看；IP 只用於頻率限制，國家只用於卡包地區判斷；產品分析不用 cookie，事件不帶身分資料。
- 結算用穩定幣：Arc 通道收 Circle 發行的 USDC，錢落在發行方自己的鏈上；每條通道收哪種幣是設定，接受的幣可以照各地法規調整。
- 不做提現：幣一直在用戶自己的錢包裡（收藏錢包或自己綁的錢包），換成法幣由用戶自己處理，平台不經手法幣。
- 偶像肖像有 IP 風險：上線後 NFT 和卡片頁只用入庫實物的掃描圖，不拿偶像照片做營銷素材。devnet 的樣本卡用 CC BY 授權照片，在 `/credits` 頁署名，不用於廣告投放。

## 測試

- 單元測試（`npm test`，vitest）：卡包機率和期望價值、抽卡公平性的重算、拍賣的加價規則（和程序同一組數字）、收件地址驗證、物流單號的整理、檢查碼和查詢連結、兩個金庫的運費（每個可寄的地方都有運費、按 0.5 進位，不寄的地方沒有）、擔保交易的填地址和寄出期限、收藏冊擺法和篩選、八種語言的鍵和參數一致、程式碼裡寫死的每個翻譯鍵都存在。
- 託管程序的測試（`onchain/tests/`）：掛單、成交、拍賣的出價鎖款和退款、結標分帳、保底價流拍、取消限制、參數範圍和延長截止，跑在本地驗證節點上（Core 程序從主網複製）。程序的 Rust 單元測試用 `cargo test`。
- 端到端測試（`e2e/`）對著跑起來的網站和 devnet 執行，每次都是真實交易，會入庫測試卡和建測試卡包，所以網站要用獨立的測試資料庫啟動（`PGLITE_DIR=.data/pglite-e2e`）：`test:e2e:vault`（入庫選金庫、卡包、公平性核對、回購、按卡所在金庫計價的提貨和取消、加拿大地址要選省份、溫哥華寄加拿大另收並分開記 GST/HST、收藏卡寄進選定的金庫並轉成金庫卡）、`test:e2e:escrow`（擔保交易：付款前要收件地址、賣家看得到而刊登頁看不到、改地址後賣家要重讀、寄出要物流單號、買家看到單號、賣家更正單號、逾時退款、申訴、自動放款、後台放款）、`test:e2e:auction`（自由刊登拍賣：沒填收件地址不能出價、得標訂單帶著出價時的地址、出價鎖款、被超過退款、結標轉成擔保訂單、保底價流拍、賣家取消、截止後的出價、假卡作廢；金庫卡拍賣：開拍、出價鎖款、被超過時同一筆交易退回、取消限制、鏈上出價紀錄；每一步該收到的站內通知，鏈上最短 1 天所以結標由合約測試驗證；網站要用 `AUCTION_DAY_SECONDS`、`AUCTION_BID_WINDOW_SECONDS`、`AUCTION_EXTEND_SECONDS` 縮短時間啟動）、`test:e2e:ui`（無頭 Chrome 注入 Wallet Standard 測試錢包，點完主要流程並截圖，包括付款方式面板、提貨表單選加拿大省份後分行顯示運費和 GST/HST、拍賣出價、後台填物流單號出貨後持有人在卡片頁看到單號）、`test:e2e:email`（郵箱帳號：驗證信、沒驗證不能刊登和綁錢包、連結只能用一次、綁定之前登入過的錢包時合併帳號、忘記密碼、重設後其他裝置登出、改密碼，最後用無頭 Chrome 走註冊和重設頁並截圖；網站不要設 `RESEND_API_KEY`，信從 `.data/outbox.jsonl` 讀，路徑可用 `E2E_OUTBOX` 改）、`test:e2e:privy`（收藏錢包：郵箱帳號建立收藏錢包、輸入 Privy 測試帳號的驗證碼並綁定，換頁或換瀏覽器後用它付款，付款不花用戶的 SOL；要設 `E2E_PRIVY_EMAIL`、`E2E_PRIVY_CODE`，Privy 後台 User management → Authentication → Advanced 開啟測試帳號）、`test:e2e:binder`（收藏冊同步：拿出冊子的標記被刪、別的裝置刪掉的卡不會回來、未送出的改動會補傳）、`test:e2e:mobile`（模擬 390×844 手機逐頁截圖，找出超出螢幕寬度的元素，檢查漢堡選單能展開和跳頁；只讀，可直接對線上站跑）。管理員錢包金鑰檔用 `E2E_ADMIN_KEYPAIR` 指定，地址要在網站的 `ADMIN_WALLETS` 裡；測試照片在執行時生成。
- GitHub Actions 每次推送跑 lint、型別檢查、單元測試和正式構建。

## 卡面圖片

- 沒有實拍圖的卡，卡面由 `src/lib/card-art.ts` 用 canvas 生成佔位圖。
- 卡片資料帶 `image` 時，3D 卡和列表卡改用實拍圖，載入失敗退回佔位圖。
- 所有照片走同一條處理流程（`src/lib/server/media.ts`）：伺服器端驗證確實是圖片，裁成 55:85、660×1020 的 JPEG，存兩份——未加浮水印的原圖留給鑑定，加了浮水印的展示圖對外提供。上傳的一組正反面只要有一張不合格就整組拒絕。
- 浮水印學 Pocamarket：半透明的白色 idolca 文字標誌斜 30° 平鋪滿整張圖，帶極淡的黑色描影，深淺背景上都看得見；裁掉一角也去不掉。正反面用同一套處理，和平台統一卡背的平鋪標誌一致。標誌用字形輪廓繪製，不依賴伺服器上的字型。
- devnet 樣本卡的照片是維基共享資源上 CC BY 授權的偶像照片，倉庫裡只記來源網址和裁切位置（`src/lib/sample-credits.json`）。某張樣本照第一次被請求時，伺服器從維基共享資源抓圖，走上面的流程入庫，之後直接從資料庫讀。圖片按網址長期快取，所以樣本照的 id 帶處理版本號（`src/lib/sample-image.ts` 的 `SAMPLE_REV`）：裁切或浮水印一改就把版本號加一，伺服器重新生成，瀏覽器和 CDN 也不會繼續用舊圖。作者和授權由 `/credits` 頁公開署名，只列金庫卡實際用到的照片。
